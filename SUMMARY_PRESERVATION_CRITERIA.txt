요약 정보 보존 재발 방지 기준 v1 — 2026-11-07

고정 범위
실행 RUN-1793881522278-ff3308의 실제 저장 요약 16개에서 확인한 오류 22개를 C01~C22로 고정했다.
원본 전문, 당시 실패 요약 전문, 출처 ID, 원본·요약 파일 지문, 실제 검토 이유를 함께 보존했다.
v1 원본과 판정은 덮어쓰지 않는다. 원본·사실·기준 변경은 새 버전으로 추가한다.
기준 파일 SHA-256과 C01~C22 목록, 건수도 테스트에서 검증한다.

네 범주
date: 사건 시각·약속·실제 도착·수령·반납·메일 발신 시점을 구별한다. 오전/오후, 변경 전/후, 인물별 시각을 묶어 검사한다.
number: 숫자와 단위, 비교 입력 수, 전후 값, 단위 정의와 측정값, 돈을 보낸/받은 방향을 묶어 검사한다.
negation: 부정 대상과 주체, 예정/완료/미확인, 다른 작업의 완료와 현재 작업의 상태를 구별한다.
condition: 조건절·선행 작업과 결과의 관계를 보존한다. 조건부 계획을 이미 완료한 사실로 바꾸지 않는다.
상태·주체·이력 오류는 관련 범주의 사실 관계에 포함한다. 해당하지 않는 범주는 NOT_APPLICABLE이며 PASS에 합산하지 않는다.

정상 변환 처리
공백·쉼표, 한글 수사/숫자, 24시간제/오전·오후, 만원/원 표기를 정규화한다.
예: 14시=오후2시=14:00, 오후3시반=15:30, 열두명=12명, 육십개=예순개=60개, 0.5만원=5,000원.
부정·조건·주체·단위·시제는 지워서 비교하지 않는다. 오전11시와 오후11시는 다르다.
정상 표현을 보강한 66개 예제와 각 사례 원본 22개가 PASS해야 한다.
추가 테스트는 다른 사람의 미완료 상태, 잘못된 주장을 부정하는 문장, 숫자가 같아도 관계가 틀린 문장 등을 확인한다.
이전 감사에서 보존을 확인한 14개 대조 사례도 참고 자료로 별도 보관한다. 이 14개는 자동 검사 통과 건수에 합산하지 않는다.

판정
PASS: 이 사례에 고정한 필수 사실을 지원 표현으로 인식했고 명시적 모순을 발견하지 않았다.
FAIL: 고정 사실과의 명시적 모순 또는 좁게 정의한 누락 조건을 발견했다.
REVIEW: 새로운 표현으로 판정할 수 없거나 실행 범위가 불완전하다. 자동 오답이나 자동 통과로 처리하지 않는다.
NOT_RUN: 해당 사례의 후보 요약이 제공되지 않았다. 전체 PASS가 될 수 없다.
한 요약 안에 정답과 명시적 모순이 함께 있으면 모순을 우선한다.

검사 성격
이 도구는 22개 오류에 대한 제한된 회귀 검사기다. 한국어 전체 의미를 판정하는 일반 평가기가 아니다.
사례의 rule.expected_atoms는 사람이 검토하는 사실 기준, required/forbidden/omissions는 자동으로 인식하는 범위다.
표현을 인식하지 못하면 REVIEW가 생길 수 있다. 새 표현은 사람이 원본과 대조한 뒤 다음 버전의 대조 예제로 추가한다.
PASS는 해당 사례의 고정 사실에 대한 결과이며, 요약의 다른 모든 사실까지 정확하다는 판정이 아니다.
출력의 근거 위치는 정규화한 텍스트 기준이다. 실제 원본·당시 요약 전문은 고정 자료에서 확인한다.

실행 방법 — 앱 폴더에서
1. 검사기 자체 점검
   node tools/check-summary-preservation.cjs --self-check
   당시 오류 22개를 모두 FAIL로 잡고 원본/수정/동치 표현 88개가 PASS인지 검사한다.
   검사기 점검 성공은 요약 모델의 정확도 향상을 뜻하지 않는다.

2. 자동 테스트
   node --test tests/summary-preservation.test.cjs
   기존 전체 테스트를 실행할 때에도 이 파일이 함께 실행된다.

3. 앞으로 생성한 요약 대조
   node tools/check-summary-preservation.cjs --candidates candidates.json --output preservation-result.json
   입력 형식: [{"case_id":"C01","summary":"검사할 요약"}, ...]
   또는: [{"source_id":"원래 출처 ID","summary":"해당 원본의 새 요약"}, ...]
   source_id 형식은 같은 원본의 여러 오류 기준을 한꺼번에 검사한다. 16개 원본 모두를 넣으면 22개 기준을 검사한다.
   두 형식 중 하나만 사용하고 알 수 없는 ID나 중복 ID를 넣지 않는다. 본문은 같은 고정 원본의 요약이어야 한다.
   종료 코드: 0=모든 기준 PASS, 1=확정 FAIL 있음, 2=REVIEW/미실행 또는 잘못된 실행 인자.
   기준을 검사할 모델 입력으로 전달하지 않는다. 요약을 생성한 다음 오프라인에서 대조한다.

실행 결과는 date/number/negation/condition별로 분리한다. FAIL·REVIEW·NOT_RUN이 남으면 전체 통과로 간주하지 않는다.
이 변경은 검증 파일 추가이며 실제 요약 생성·검색·답변 경로에 자동 차단이나 새 모델 호출을 추가하지 않는다.
