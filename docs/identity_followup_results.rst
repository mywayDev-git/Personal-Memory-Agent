동명이인 후속 질문 수정 및 응답 비교
=================================

독립 확인 자료를 먼저 고정한 뒤, 후속 질문의 이름·관계·역할을 보존하도록 수정했다.
이 문서는 이전 ``first_response_results.rst``와 구분되는 후속 실험 기록이다.
기반 모델과 최종 독립 검증 수준은 유지했다. 개인 DB와 공식 메인 평가는 사용하지 않았다.
기준은 Qwen3-8B Q4_K_M·BGE-M3 Q8_0, Windows의 i7-13700·RAM 16GB·RTX 3060 8GB 환경이다.

수정과 자료 고정
---------------

* 브랜치: ``codex/first-response-cpu-gpu``. 제품 수정 코드: ``f47ae4c``.
* 새 합성 독립 사례 16개는 제품 변경 전 ``1abe39b``에서 고정했다.
  자료 SHA256: ``3c96825dafc2975ff7ca0b9c9e0410754ae137136545137940463da37f4e810a``.
* 기존에 공개된 실패 자료는 회귀 재현용이다. 새 독립 자료로 다시 이름 붙이지 않는다.
* ``그 친구``가 참조 해석에서 빠져 있었고, ``그 친구 직업``이 잘못된 역할·이름으로
  인식될 수도 있었다. 지시 표현과 명시적 역할을 구분하도록 고쳤다.
* 직전 사용자 질문과 검증된 원문 인용으로 유일하게 확인한 역할만 이어받는다.
  검증 실패·명확화 요청·인용 부재·여러 사람·친구의 친구 질문에서는 임의로 정하지 않는다.
* 후속 해석 모델이 다른 역할을 추가해도 원래 역할을 기준으로 독립 검증하고 별도 검사한다.
  한 원문에 동명이인이 함께 있어도 검증 모델이 선택한 정확한 문장의 역할을 확인한다.
* 직업을 묻는 동등한 표현도 좁게 처리하며, 계획·부정·복합 질문까지 직업 조회로 바꾸지 않는다.
  원문 인용 답변 후보도 항상 새 독립 모델 검증을 통과해야 한다.
* API 응답·DB 스키마·기본 모델은 유지했다. 검증 캐시 무효화를 위해 프롬프트 버전은 9다.

품질 확인
---------

알려진 ``final_pronoun`` 오류는 수정 후 GPU 기준·후보 모두 올바른 동아리 친구의 직업만
답하고 검증을 통과했다. 함께 확인한 역할·단순 사실·날짜 4개도 양쪽 모두 통과했다.

새 독립 확인 16개는 GPU 기준 16/16, 후보 16/16, 중요한 오답 승인 0건이었다.
실제 답변·정확한 인용문 32개를 합성 원문에 대조한 에이전트 검토도 일치했다.
이는 사용자 검토를 대신하지 않으며, 작은 자료 집합으로 모든 동명이인 표현의 정확성을
보장하지 않는다. 모호한 이름만 있는 경우 두 역할을 되물었고 계획과 실제 실행도 구별했다.
제품·평가 코드가 실행 중 바뀌지 않은 것을 해시로 확인했다.

속도 비교의 기준과 후보에는 모두 같은 역할 보존 수정을 적용했다.
후보만 통합 중간 판단·검색 확장 출력 제한·검증된 날짜 원문 후보·명시적 인물 해석
재사용 옵션을 켰다. 원문·후보를 잘라내거나 최종 검증을 생략하지 않았다.
모델 최초 로딩·색인·앞선 대화 준비·준비 실행은 답변 처리 시간과 분리한다.

CPU 사전 확인과 스레드 시험
-------------------------

CPU 강제 실행은 생성·임베딩 GPU 오프로딩을 모두 끈다. 물리적으로 GPU가 없는 PC를
검증한 것은 아니다. 다른 앱은 유지한 16GB 환경이다.

입력 처리 스레드 16개의 각 1회 비교에서 단순 사실은 155.951 → 93.843초,
날짜는 194.296 → 88.360초였다. 양쪽 답변과 근거 검사를 통과했지만 중앙값이 아니다.
후속 질문의 앞선 대화를 CPU에서 준비하는 과정은 300초 제한에 걸렸다.
이를 답변 성공이나 준비 시간 제외만으로 해결된 제품 문제로 표시하지 않는다.
부분 결과와 실패한 합성 DB를 보존했고 일반 서버는 복구했다.

후보의 동일 단순 사실 입력을 바꾼 스레드 시험은 다음 각 1회 관측이다.
생성 토큰 처리 스레드는 8개로 유지했고 입력 처리 스레드만 바꿨다.

================== ============== ===============
입력 처리 스레드   후보 시간(초)  자동 품질
================== ============== ===============
16                 93.843         통과
24                 82.757         통과
8                  99.385         통과
================== ============== ===============

24개를 후속 반복 측정 조건으로 선택했다. 이 작은 시험만으로 다른 CPU에서도 최선이라고
판정하거나 앱·일반 서버의 기본 설정을 바꾸지 않았다. CPU 60초 목표는 이 시험에서 미달이다.
16개 시험의 통합 판단 약 37초와 독립 검증 약 42초 중 대부분은 입력 처리 시간이었다.

검증된 앞선 대화를 공유하는 측정
------------------------------

``-AnchorTemplates``는 완료된 합성 실행의 대화만 가져온다. 파일·모델·질문 집합 해시,
전체 원문과 기록 ID, 단일 완료 대화, 질문, 기존 인용 정답을 다시 확인한다.
원본 DB를 변경하지 않고 각 측정 DB에 복사한다. 모델 호출 없이 같은 앞선 대화를
CPU·GPU 및 기준·후보에 제공하여 입력 차이를 줄인다.
이 경로의 결과에는 ``target_device_preparation_verified=false``를 명시한다.
CPU가 그 앞선 대화를 실제로 준비하는 데 성공했다는 뜻이 아니다.

사용자가 확인하고 실행하기
-------------------------

독립 질문과 정답 조건의 계획만 보려면 작업 폴더에서 실행한다::

    & C:\development\Personal-Memory-Agent\.venv\Scripts\python.exe -m evaluation.first_response --split identity_confirmation

실제 독립 품질 비교의 계획은 다음과 같다. ``-Execute``가 있어야 모델을 구동한다::

    ./scripts/run_latency_goal.ps1 -Placement gpu -QualityScreen -IntermediatePlanning -BoundedExpansions -SourceDateDrafts -ContextShortcut -ColdInterpretations -FixtureSplit identity_confirmation -PythonExe C:\development\Personal-Memory-Agent\.venv\Scripts\python.exe -PauseOrdinaryModels -RunName my-identity-check

``-PauseOrdinaryModels``를 사용하면 알려진 일반 서버 두 개만 임시 종료하고 종료 시 복구한다.
``-CandidateOnly``는 후보만 시험하는 도구 옵션이며, 기준이 없어 비교나 개선율을 확정하지 않는다.
``-GenerationBatchThreads``는 입력 처리 스레드를 지정한다.
기존 실패 결과를 덮어쓰지 않도록 매번 새로운 ``RunName``을 사용한다.
각 결과 폴더의 ``answers.html``에서 질문·답변·정답 조건·정확한 인용·전체 원문을 확인한다.

원시 자료
---------

* ``.local/latency-goal/identity-repair-known-regressions``: 공개 실패의 회귀 확인.
* ``.local/latency-goal/identity-confirmation-v1``: 새 독립 16개·품질 판정·원문 대조 검토.
* ``.local/latency-goal/identity-repair-cpu-screen``: CPU 사전 확인·300초 준비 실패.
* ``.local/latency-goal/identity-cpu-batch24-probe`` 및 ``identity-cpu-batch8threads-probe``: 스레드 시험.

전체 앱의 기존 긴 원문 처리 제한이 해결되었다고 주장하지 않는다.
기본 프로젝트 체크아웃·앱 기본 모델·다른 실험 자료를 유지하며 자동 병합하지 않는다.

추가 검색 종료 시제품의 별도 탈락
--------------------------------

GPU 5회에서 후속 질문이 약 17.6% 개선에 그쳐, 이미 명확한 사람에게 강제로 덧붙이는
전체 지인 검색을 줄이는 별도 시제품을 만들었다. 다른 인물·역할·직업·날짜의 독립 자료
16개를 ``7e7818d``에서 먼저 고정했다. SHA256은
``4413d478ac313f2b9bbfdd3d39b80fbf040184cc6d4099f2972f36209a541f0e``이다.
이 자료는 후보 16/16이었지만, 추가 오프라인 점검에서 역할과 키만 있는 원문도 직업 조회를
완료했다고 여길 수 있는 빈틈을 찾았다. 사례 통과만으로 이 구현을 채택하지 않았다.
어휘 치환으로 일부 조사가 어색한 합성 문장이 있으나 동결 후 원문과 점수는 바꾸지 않았다.

이를 보완하는 시제품은 현재 요청의 원문 인용 답변을 새 독립 모델 검증에 먼저 보낸다.
검증이 ``fulfillment=direct``로 승인했을 때만 추가 검색을 종료한다. 같은 질문·대화·원문·버전의
현재 요청 결과만 전달하며, 변경되면 새로 검증한다. 부분 답변·거절·잘못된 출력은 기존 검색을
유지하고 취소·시간 초과·원문 변경은 그대로 전파한다. 이전 요청의 검증을 캐시하지 않는다.

불완전한 직업 근거와 별도 직업 기록을 포함한 독립 16개를 ``c2b3475``에서 다시 먼저 고정했다.
SHA256은 ``5f6da565d7b29657cde3d251cd9e543d3965246e2ed4ef860bf73fe7d7dfb893``이다.
이 마지막 자료는 14/16으로, 두 실패 때문에 고급 프로필의 최종 채택을 차단했다.

* 직업 미기록의 명시적 역할 질문: 직업 정보가 없다는 결론은 맞았지만 다른 사람의 키·직업
  기록을 함께 인용했다. 자동 문구 채점 실패와 별개로 인용 범위 오류를 실패로 유지한다.
* 같은 사람을 묻는 후속 직업 질문: 키 172cm 원문만 답하고 검증을 통과했다. 다른 직업을
  사실로 주장하지는 않았지만, 질문에 답하거나 직업 미상이라는 한계를 설명하지 못했다.
* 두 실패 모두 ``identity_completion_probes=0``이었다. 새 검색 종료 분기가 아니라 기존
  일반 생성·검증 경로에서 나왔으므로 새 시제품이 원인이라고 단정하지 않는다.
* 최종 확인 자료의 답에 맞춰 규칙·문구 채점·임계값을 고치지 않았다. 정답 기준은 합성 원문이다.
  정상적인 한계 설명과 인용 오류·답변 미완료를 구분해 원문 대조 기록에 남긴다.

``scoped_identity_search``는 제품 환경 변수로 켤 수 없게 했다. 평가 도구의
``-ScopedIdentitySearch``는 탈락 시제품을 명시적으로 재현하기 위한 연구 옵션으로만 남긴다.
이는 일반 앱에 적용된 최적화나 품질 통과 프로필이 아니다. 오프라인 검사는 마지막 정책 변경 후
1007개 통과했으며, 실제 모델의 위 두 품질 실패를 오프라인 검사 통과로 덮지 않는다.

첫 GPU 5회 비교
--------------

모델 준비 실행을 제외하고 각 사례의 기준·후보 순서를 교대했다. 가속은 GPU,
생성 토큰 스레드 8개·입력 처리 스레드 24개다. 여기에는 탈락한 추가 검색 종료 옵션을
넣지 않았다. 기준과 후보에 같은 인물 범위 수정을 적용했다.

================= =================== =================== ============= =============
사례              중앙값 기준→후보(초) 최대 기준→후보(초) Qwen 호출      사례별 선별
================= =================== =================== ============= =============
단순 사실         16.439 → 10.067     17.140 → 10.156       5 → 3         부분 개선
날짜              21.278 → 9.769      21.594 → 9.816        7 → 3         선별 통과
대명사 후속       50.848 → 41.915     51.015 → 42.010      12 → 11        미채택
복합              40.387 → 32.008     40.641 → 32.321      12 → 9         선별 통과
================= =================== =================== ============= =============

각 사례에서 양쪽 5/5 정답·독립 검증 통과, 오류·시간 초과 0건이었다. BGE 호출은 단순 사실·날짜
각 요청 1회, 후속·복합 각 요청 2회였다. 단순 사실 약 38.8%, 날짜 약 54.1%, 후속 약 17.6%, 복합 약 20.7% 단축이다.
후속 RAM 피크는 4775 → 5257 MiB로 약 10.1% 늘어 5% 조건에도 실패했다.
다른 세 사례는 RAM·private commit·장치 VRAM의 5% 증가 제한 안에 있었다.
사례별 선별 통과는 전체 품질·전체 앱 프로필 채택을 뜻하지 않는다.

이전 실패를 포함한 자료와 현 실행을 모두 보존했다. 데이터·소스·실행 인자와 모델 해시는
각 원시 ``results.json`` 및 ``launch-plan.json``에서 확인한다. 성능 로그에 개인 원문을 넣지 않았다.

단순 질문 GPU 후보 20회 확인
--------------------------

고급 검색 종료 옵션을 끈 같은 단순 질문 후보를 준비 실행 후 각 20회 확인했다.
첫 5회와 별도 실행이며, 기준 경로 20회를 함께 측정한 비교는 아니다.

=============== =============== =============== ============= ===============
사례            중앙값(초)      최대(초)        자동 품질     GPU 10초 목표
=============== =============== =============== ============= ===============
단순 사실       10.049          10.904          20/20         미달
날짜             9.768           9.830          20/20         시간 조건 충족
=============== =============== =============== ============= ===============

두 사례 모두 오류·시간 초과 0건이었다. 단순 사실 중앙값을 10초로 반올림해 목표 달성으로
표시하지 않는다. 해당 날짜 사례의 시간 조건 충족을 전체 질문·전체 앱 품질 통과로 확대하지 않는다.
20회도 관측한 자료 범위의 결과이며 사용자 전체 요청의 P95 보장이 아니다.

단순 질문 CPU 5회 비교
---------------------

고급 검색 종료 옵션을 끄고 준비 실행 후 기준·후보를 각 5회 교대했다.
생성 토큰 스레드 8개·입력 처리 스레드 24개이며 두 모델 모두 GPU 오프로딩을 끈다.
각 실행 안에서 기준·후보는 같은 합성 seed DB를 복사한다. CPU·GPU 실행은 같은 원문·질문·모델을
사용하지만 장치별 색인의 DB 바이트 해시까지 같다고 주장하지 않으며 각 해시를 따로 보존한다.

메모리 5% 증가 제한과 최댓값 10% 악화 제한을 통과했지만 60초 목표는 달성하지 않았다.

각 요청의 사실 검증과 답변은 완료됐고 기존 코드가 표시 제안을 폐기해 처리했다.
통신 로그에는 정확한 예외 유형이 없으므로 이를 특정 예외로 단정하지 않는다.

단순 질문 메모리 비교
-------------------

아래는 각 5회의 피크다. 단위는 MiB이며 ``RAM``은 평가 프로세스·모델 서버의 working set 합,
``private``는 private commit 합이다. 공유 페이지 중복과 표본 사이의 짧은 피크 가능성이 있다.
VRAM은 다른 앱을 포함한 장치 전체 관측값이며 CPU 행의 VRAM을 모델 오프로딩 사용량으로 보지 않는다.

=============== ================= ================= =================
조건            RAM 기준→후보     private 기준→후보 VRAM 기준→후보
=============== ================= ================= =================
GPU 단순 사실   6600 → 6758       10502 → 10501     7740 → 7740
GPU 날짜        5663 → 5641       10528 → 10504     7773 → 7773
CPU 단순 사실   5379 → 5368        8201 → 8194       537 → 537
CPU 날짜        5413 → 5414        8205 → 8203       735 → 535
=============== ================= ================= =================

추가 메모리 절감이 일관되게 확인된 것으로 표현하지 않는다. 단순 질문의 증가 폭은 5% 이내였다.
CPU 날짜 후보 처리 중 시스템 여유 RAM 최소는 14.1 MiB, GPU 단순 사실 20회 실행에서는
18.7 MiB였다. 다른 앱을 유지한 이 환경의 관측값이며 모든 작업의 안정성을 보장하지 않는다.
서버 로딩 메모리는 원시 파일의 ``startup.memory``에 별도로 있다.

CPU의 동명이인 후속 질문 확인
---------------------------

검증된 GPU 합성 앞선 대화를 공유한 CPU 강제 실행 1회에서 ``그 친구는 어떤 일을 해?``는
사진 동아리 친구 은호의 도예가 직업만 답하고 원문의 같은 문장을 인용했다.
회사 동료 은호의 직업은 병합하지 않았다. 정답·인용·인물 범위·독립 검증을 통과했다.
현재 질문 처리 시간은 181.624초, Qwen 5회·BGE 1회였다. 준비 실행 없는 품질 확인 1회이며
속도 중앙값·20% 개선·전체 요청의 P95 보장으로 표시하지 않는다.
이 실행의 RAM 8378 MiB·private commit 7644 MiB·장치 VRAM 535 MiB는 다른 입력·이력·준비 조건의
관측값이므로 위 단순 질문 5회에 대한 메모리 개선율로 계산하지 않는다.

CPU의 후속·복합 전체 5회 채택 비교는 수행하지 않았다. 고급 프로필의 절대 품질 선별 실패와
이전 CPU 대화 준비 실패를 남기고, 검증된 단순 질문의 반복 측정과 원래 오류의 CPU 확인을 분리했다.
따라서 CPU 복합·후속 20% 단축 조건이나 같은 전체 입력 반복 캐시 조건의 최종 통과를 주장하지 않는다.

최종 상태와 자료
---------------

확인한 기존 동명이인 후속 혼합 답변은 브랜치에서 수정했고 새 독립 16개와 실제 CPU 후속 질문을
통과했다. 단순 질문의 호출·시간도 줄었지만 GPU 사실 10초·CPU 60초와 전체 품질 조건은 미충족이다.
직업 미기록 상황의 인용·답변 완결성 문제는 남았으며 고급 검색 종료 프로필은 채택하지 않았다.
기본 모델 교체·기본 프로젝트 브랜치 변경·자동 병합은 하지 않았다.

1007개 오프라인 검사가 통과했다. 공식 메인 평가는 별도 요청 없이 실행하지 않았다.
8081·8082 일반 서버는 마지막 측정 직전의 정확한 실행 설정으로 복구했고 health 200을 확인했다.
소유 실험 모델 서버 18581·18582는 남아 있지 않았다. 다른 앱과 개인 DB는 유지했다.
현재 작업 폴더 ``.local`` 전체는 약 17.20 GiB, 남은 디스크는 약 17.95 GiB로 제한 안이었다.

* ``docs/identity_followup_results.json``: 관측값·모델 호출·메모리·오류·파일 해시·실험별 상태.
* ``.local/latency-goal/identity-simple-gpu-twenty``: GPU 후보 20회 확인.
* ``.local/latency-goal/identity-simple-cpu-five``: CPU 기준·후보 각 5회 비교.
* ``.local/latency-goal/identity-rootfix-cpu-role-confirmation``: 원래 후속 문제의 CPU 단일 확인.
* ``.local/latency-goal/identity-verified-completion-confirmation-v3``: 확장 품질 14/16 및 두 실패.
* ``.local/identity-final-offline-tests.xml``: 최종 오프라인 검사 기록.
* ``.local/identity-final-server-state.json``: 서버 설정 복구·health·잔류 서버 확인.

실행별 ``answers.html``은 읽기 전용 검토표다. 열거나 다시 읽는 것만으로 모델이나 평가를 실행하지 않는다.
새로운 실제 실행은 기존 안내처럼 명시적 ``-Execute``가 있어야 시작한다.
