문맥 목표와 행동 — V2

입력을 하나의 의도 종류로 분류하는 단계를 거치지 않는다. 모델이 최신 입력, 역할이 구분된 대화, 대기 목표, 실제 자료함과 조회 결과를 읽고 사용자 목표를 자연어로 정리한다. 하나의 계획에 조회·새 기록·수정 등 여러 행동을 포함할 수 있다. 공감·조언·답변을 서로 배타적인 실행 경로로 분리하지 않는다.

처리 과정

1. 선택한 자료함을 읽는다. 가상 자료함은 구분 없이 전체 199개 원문이다. 앱의 읽기 전용 사전 조회는 모델이 요청한 행동과 따로 기록한다.
2. goal_plan에서 목표, 사용한 맥락, 연결한 발언, 필요한 도구 단계들을 함께 준비한다. 도구가 필요하지 않으면 단계 목록은 비어 있다. intent나 단일 action 분류 필드는 없다.
3. 도구를 실행한다. 검색은 실제 조회한다. 기록 변경은 원문 출처와 기록 버전이 묶인 확인 초안을 만든다. 필요한 경우에만 그 도구의 대상·본문·대화 보관 범위를 준비한다.
4. goal_response에서 현재 목표와 실제 도구 결과를 보고 답한다. 확인 불가·충돌·추가 질문 등은 이 시점의 응답 결과이며 앞선 도구 경로를 고르는 입력 의도 분류가 아니다.
5. 기록 변경은 각 초안의 확인 버튼으로만 반영한다. 여러 초안의 확인·취소·영수증을 별도로 보관한다. 확인 후 기존 답변이나 다른 초안, 새로 작성한 입력을 지우지 않는다.

화면

- 상단: V2 · 문맥 목표와 행동.
- 답변 아래: 이번 목표, 필요한 행동들, 실제 완료·확인 대기·구분 필요·실패 상태.
- 요청·응답 플로팅: 사용자 목표 → 사용한 대화 맥락 → 계획한 행동과 실제 결과 → 앱의 사전 조회 → 확인 초안과 영수증.
- 테스트 모드를 켜고 보낸 요청: 실제 모델 호출의 입력·출력도 보관한다.
- 이전 대화는 당시 저장된 값으로 표시한다. 실행 당시 선택지가 없으면 임의로 8개 분류 목록을 붙이지 않는다.

계획과 실제 변경

목표 계획을 요청 ID에 묶어 보관한다. 실패 후 같은 제출본을 재시도하면 같은 계획과 이미 준비한 초안을 재사용한다. 각 초안은 독립된 실행 ID와 원문 버전을 갖는다. 실패한 단계가 있으면 준비된 다른 초안은 유지된다. 저장·수정·삭제 완료는 실제 실행 영수증으로 확인한다. SQLite 기록 변경과 영수증은 같은 트랜잭션으로 반영한다.

기존 V1은 비교용 처리 경로다. 새 처리 과정은 V2에 적용한다. 기존에 실제 변경 초안이 준비됐거나 실행 영수증이 있는 과거 요청을 새 계획으로 자동 재실행하지 않는다.

직접 확인할 예

화면을 새로고침하고 V2를 선택한 뒤 다음을 확인할 수 있다.

- 일반 계산: 목표는 계산 질문에 답하는 것이며, 감정·기억 의도 중 하나를 고르는 화면이 없어야 한다.
- 이미 기록된 주제로 조회와 새 경험 기록을 함께 요청: 조회 답변과 저장 전 초안이 함께 나와야 한다.
- 감정을 나누면서 작은 조언과 기록도 함께 요청: 답변을 생략하지 않고 기록 초안을 별도로 보여야 한다.
- 기록 두 개를 각각 수정·삭제 요청: 대상별 초안과 확인 버튼이 나와야 한다. 하나만 확인하면 다른 초안은 대기 상태로 남아야 한다.
- A 제출 후 새 입력 B 작성: A의 확인·취소·재시도가 B를 지우지 않아야 한다.

이 변경 작업에서는 기능 테스트·자동 테스트·로컬 모델 테스트를 실행하지 않았다. JavaScript 문법만 확인했다. 기존 실행기와 199개 조회 테스트의 모의 응답 및 도구 스크립트는 새 응답 구조에 맞춰 갱신했으며, 실행은 사용자가 진행한다.
