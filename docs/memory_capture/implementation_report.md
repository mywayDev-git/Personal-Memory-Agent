## 구현 위치

- `pma/memory/schemas.py`, `repository.py`, `provenance.py`: 형식, 원자적 저장, 소유권, 출처, 보관, 만료 정리.
- `pma/memory/manager.py`, `conflict_resolver.py`, `deduplication.py`: 추출·검색 후보 선정·의미 비교·승인 리뷰.
- `pma/memory/api.py`, `pma/chat/memory_capture.py`, `pma/chat/api.py`: API와 자연어 저장 의도.
- `pma/processing.py`: AI 제안·가설·계획·결정의 검색용 사실 상태 보존.
- `pma/static/memory.js`: 미리보기·비교·관리·이력 화면. `chat.js`와 `style.css`에서 연결·반응형 표시.
- `evaluation/memory_capture_eval.py`, `memory_relations_eval.py`, `memory_resources.py`, `memory_capture_benchmark.py`: 실제 로컬 모델 및 성능 평가.
- `evaluation/memory_ui_server.py`, `tests/memory_capture_ui.mjs`: 운영 데이터에 접근하지 않는 반복 UI 평가.

## 저장 계약

후보를 만드는 것은 개인 기억의 저장이 아니다. 승인 전 후보는 검색 snapshot에 들어가지 않는다. 원문과 후보는 24시간 유효하며 만료 시 재선택한다. 만료된 후보 행은 30일 유예 후 기존 유지보수 작업에서 정리한다. 승인된 기억의 출처 스냅샷은 별도로 유지한다.

웹 승인에는 완료된 review_id가 필요하다(기존 기억이 없는 최초 저장의 API 호환 예외는 트랜잭션 안에서 다시 검사). 모델 실패 시 승인을 차단하고 비교 재시도를 제공한다. 편집 이후에는 재비교한다. 비교 도중 다른 기록이 변경되면 REVIEW_STALE이다. 추론은 DB 쓰기 잠금을 잡지 않는다.

AI 제안은 저장 승인이나 정정으로 사용자 실행 사실이 되지 않는다. 기존 record 별칭 접근도 원래 출처와 사실 상태를 유지한다. 같은 의미/원문 중복은 저장을 막고 기존 기록을 보여준다. 충돌은 자동 삭제·자동 병합하지 않으며 별도 추가 또는 명시적인 정정을 선택한다.

삭제는 기존 30일 휴지통 및 복구 API를 사용한다. 보관은 원문과 이력을 유지하면서 검색과 대화 선호에서 제외하고, 보관 해제 시 다시 색인한다. GENERAL은 승인된 최근 사용자 선호만 전달하며 개인 사건 검색을 새로 강제하지 않는다.

## 검증 해석

구체적인 실행 수치는 test_results, regression_report, performance_comparison에 있다. 로컬 모델 판정은 원문 해석이며 객관적인 사실 검증이 아니다. 전체 언어 표현과 대규모 데이터에 대한 정확도를 보장하지 않는다. 현재 저장소에 없는 과거 606개 테스트와 완전한 보조기기 감사는 실행했다고 주장하지 않는다.
