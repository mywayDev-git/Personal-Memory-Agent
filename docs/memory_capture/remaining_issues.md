# 운영 범위와 검증 제한

핵심 선택적 저장 기능과 확장 관계 검토·출처·수명주기·정책을 구현했다. 다음은 제품 범위 또는 검증의 한계다.

- 호스트는 기존 단일 로컬 계정이다. 저장소 소유권과 세션 교차 접근을 차단하지만 다중 사용자 로그인 서비스를 새로 제공하지 않는다.
- AUTO는 명세의 MVP 정책에 따라 비활성이다. SUGGEST도 후보만 제안하고 승인은 항상 사용자에게 받는다.
- 자연어 즉시 저장 의도는 보수적 한국어 규칙이고, 대화 전체 후보 선택과 관계 판정은 기존 Qwen을 사용한다. 모호한 참조를 임의로 확정하지 않는다.
- 8개를 초과하는 기록은 검색 상위 8개를 의미 검토한다. UI에 전체 수와 검토 수를 표시한다. 모든 장기 기록의 전수 의미 비교나 전역적인 무중복 보장은 아니다.
- 실제 모델 관계 평가 8개는 개발 중 사용한 작은 합성 세트다. 별도 대규모 비공개 정답 세트의 성능으로 해석할 수 없다. 초기 실패와 재실행 결과를 보존했다.
- 과거 보고서의 606개 테스트 소스는 현재 체크아웃에 없다. 현재 존재하는 테스트와 새 회귀, 실제 모델 평가만 실행했다.
- 390px 화면, 접근성 이름, native dialog 포커스/키보드 동작을 확인했다. 모든 모바일 기기·스크린리더 조합에 대한 인증은 아니다.
- 브라우저 도구가 native confirm에서 정지하여 삭제 확인을 HTML dialog로 바꿨다. 삭제 API/검색 제외는 테스트했으며 변경한 마지막 삭제 화면의 추가 브라우저 검증 결과는 test_results에 별도로 기록한다.
- 자원 측정은 평가 Python RSS와 공유 GPU 전체 사용량이다. 이미 실행 중인 모델 서버의 단독 RAM/VRAM 기여도 또는 콜드 스타트 비용을 분리하지 않았다.
