# Personal Memory Agent 메인 테스트

이 평가는 **사용자가 요청하거나 관제실의 실행 버튼을 눌렀을 때만 실행하는 공식 평가**입니다. 일반 코드 검사,
전체 pytest, 앱 시작, CI, 평가 관제실 접속은 이 평가를 실행하지 않습니다.
평가 체계 구현 요청도 실제 모델 평가 실행 요청으로 해석하지 않습니다.

## 현재 준비 상태

- 첨부 명세의 15개 영역, 489개 변수를 전체 카탈로그로 등록했습니다.
- 정상·경계 사례, 원본 변수 ID, 원문 명세 위치, 관련 구현·기존 테스트를 연결했습니다.
- 실제 제품 실행 어댑터는 기록 추출·검색·대화·후속 질문·수정·삭제·새 세션·명시적
  저장과 비저장·내부 owner 세션 격리·TXT/Markdown 가져오기를 지원합니다.
- 확장 사례에는 pairwise 표현/무관 기록/순서 조합, 임베딩 연결 장애 후 복구,
  동시 검색·저장·삭제, 100·1,000·10,000건 합성 기록 평가가 포함됩니다.
- 수동 검토로만 등록했던 항목에도 합성 입력·실제 질문·기준 답변을 연결했습니다.
  제품의 추출·검색·대화 경로를 실행해 실제 답변을 수집하고 기준 답변·필수/금지 사실과 비교합니다.
  빈 입력·길이 초과·미지원 파일은 실제 제품의 입력 검증 결과를 대조하며 모델 정확도에서는 제외합니다.
- 기존 답변 비교 사례에 추가 동작 검사를 연결했습니다. [365개 변수별 실제 검사](behavior_test_coverage.md)를 확인할 수 있습니다. **답변 비교 하나가 원본 변수 전체 검증을 의미하지는 않습니다.** 화면 배치·공유 권한·일부 장애 등
  답변 외 조건이 연결되지 않은 항목에는 `coverage_gaps`를 표시합니다. 관련 답변이 일치해도
  이러한 항목을 전체 기능 통과로 확정하지 않습니다. 일부 항목은 해당 변수의 기본 답변 예시만
  실행하므로 세부 조건의 검증 완료로 해석하면 안 됩니다.
- 현재 분류의 `UNKNOWN`은 영역별 코드 후보만 연결하고 변수의 지원 여부를 확정하지 않았다는 뜻입니다.
  `PARTIAL`은 실제 실행 어댑터를 연결했으나 변수 전체를 검증하지 않았다는
  뜻입니다. 실제 기능 현황과 실행 결과는 다릅니다. 미구현을 구현됨으로 추정하지 않습니다.
- v5 구현 보완 당시에는 실제 평가를 실행하지 않았습니다. 이후 사용자 요청으로 완료된 v5 평가를 검토해 v6으로 보완했습니다. **v6 실제 모델 평가는 미실행**이며 기존 실행 결과와 합격선을 보존합니다.

원본 명세: [사용자 행동 변수 명세](main_test_reference.md).
카탈로그·실행 사례·기본 모델 목록은 `evaluation/main_suite/data/`에서 확인할 수 있습니다.
문서의 명령은 저장소 루트에서 가상환경 Python으로 실행합니다.

## 실행 요청과 범위

| 사용자의 요청 | 프로필 | 모델·데이터 | 반복 |
|---|---|---|---|
| 메인 테스트 실행 | `core` | 현재 조합, P0 전체 카탈로그와 P1 대표 사례 | 1 |
| 모델 비교 테스트 | `compare` | 명시한 로컬 후보, 개발용 데이터 | 3 |
| 확장 테스트 | `extended` | 현재 조합, 조합·부하·동시 작업·장애 | 1 |
| 최종 후보 검증 | `final` | 명시한 후보, 최종 검증용 데이터 | 5 |

P0 전체 카탈로그가 핵심 실행에 포함됩니다. P1은 정상 대표 사례만 포함합니다.
최종 검증에 배정된 원문·질문은 핵심 실행에서 소비하지 않으며, 해당 변수의 카탈로그
행은 독립된 연습 데이터로 답변 경로를 확인합니다. 이 참고 검사는 모델 정확도와 후보 순위에서
제외하며 해당 최종 시나리오의 검증을 대신하지 않습니다.

먼저 모델을 열거나 서버를 시작하지 않는 정적 실행 계획을 확인할 수 있습니다.

```powershell
./.venv/Scripts/python.exe -m evaluation.main_suite
./.venv/Scripts/python.exe -m evaluation.main_suite --profile final
```

다음 명령은 **명시적 실행 요청을 받은 경우에만** 사용합니다.

```powershell
./.venv/Scripts/python.exe -m evaluation.main_suite --execute --profile core --output .local/main-suite/baseline-001
```

별도 프로필 예시:

```powershell
./.venv/Scripts/python.exe -m evaluation.main_suite --execute --profile compare --models .local/main-suite-models.json --output .local/main-suite/compare-001
./.venv/Scripts/python.exe -m evaluation.main_suite --execute --profile extended --output .local/main-suite/extended-001
./.venv/Scripts/python.exe -m evaluation.main_suite --execute --profile final --models .local/main-suite-finalists.json --output .local/main-suite/final-001
```

확장 평가에서는 실제 추출·임베딩을 수행하므로 10,000건 처리는 매우 오래 걸릴 수
있습니다. 개별 확장 사례는 `--case EXT-records-100`처럼 지정할 수 있습니다.
부분 실행은 공식 모델 추천에 사용하지 않습니다.

중단은 Ctrl+C, 재개는 **동일한 명령에 `--resume` 추가**입니다. 데이터·코드·모델·설정이
달라지면 같은 실행을 재개할 수 없습니다. 완료된 실패와 검토 대기도 다시 실행하지 않습니다.
실패를 재측정하려면 보고서의 재현 명령으로 새 실행 폴더를 사용합니다. 원래 시도는 보존합니다.

## 데이터와 모델 격리

- 실행 출력은 이 저장소의 `.local/main-suite/<실행 이름>` 아래에만 허용합니다.
  개인 데이터 경로와 경로 연결을 거부합니다.
- 각 후보·반복·사례는 별도 합성 DB를 사용합니다. 원문, 버전, 사건 시각과 저장 시각,
  삭제 상태를 대조합니다. 운영 DB를 읽거나 재색인하지 않습니다.
- 기본값은 전용 18481·18482 포트입니다. `--port`로 다른 전용 포트를 지정할 수 있습니다.
  사용 중인 포트는 실패 처리하며 기존 앱 서버를 재사용하거나 종료하지 않습니다.
- 실행기가 시작한 프로세스만 종료합니다. 모델은 다운로드하지 않습니다.
- 기본 등록 파일은 Qwen3-8B Q4_K_M·BGE-M3 Q8_0입니다. 등록 실행 설정은 CPU입니다.
  GPU 레이어가 0이면 장치·호스트 연산·KV 오프로딩도 명시적으로 끕니다.
  이전의 `-ngl 0`만 사용한 실행은 GPU 보조 연산 가능성이 있어 엄격한 CPU 전용 속도와 구분합니다.
  실제 사용 설정이 GPU라면 별도 모델 목록에 `gpu_layers`를 명시하고 같은 조건으로 비교합니다.
- 최초 baseline 생성 모델은 파일 해시를 계산해 실행 명세에 고정합니다. 추가 후보는 사전에
  `sha256`을 기입해야 합니다. 해시 불일치는 실행 오류로 처리합니다.
- 생성 모델 비교에서는 임베딩을 고정합니다. 임베딩 비교에서는 baseline의 실제 추출
  결과를 복사하고 후보 전용 임베딩을 새로 만듭니다. 상위 2×2 조합은 별도 `--e2e`
  실행으로 추출부터 재검증합니다. 참고 순위와 조합 재검증 결과를 구분합니다.
- 작업 중 제품 코드를 수정하거나 앱 기본 모델을 바꾸지 않습니다.

모델 목록은 기본 `models.json` 구조를 복사합니다. `generation`과 `embedding`에
`baseline`을 유지하고 추가 후보 이름을 등록합니다. 각 후보는 경로·SHA-256·문맥 길이·
스레드 수·GPU 레이어 수를 지정합니다. 임베딩 후보는 차원·pooling·입력 profile도 지정합니다.
예: Qwen 임베딩은 실제 모델의 요구사항에 맞는 `last` pooling과 `qwen3-retrieval-v1`을
설정합니다. 파일 형식만 맞는다고 모델 호환성을 가정하지 않습니다.

## 정답과 판정

기준 시각은 `2026-10-20T10:00:00+09:00`입니다. 정답은 모델이 생성하는 기억 ID 대신
원문 기록 ID·버전·문자 구간과 필수/금지 사실·기대 동작으로 정의합니다.
복수 근거는 그룹별로 하나 이상의 허용 출처를 요구합니다.
모델 검증용 시나리오 계열은 약 70:30으로 분리하며 표현 변형은 같은 계열에 둡니다.
같은 질문이나 같은 정답 원문을 재사용하는 계열도 함께 묶어 개발용과 최종 검증용에 걸치지 않게 합니다.
통계 비교에서도 이 묶음을 독립 표본 단위로 사용하여 반복 예시를 서로 독립적인 증거로 세지 않습니다.
카탈로그 참고 검사와 확장 변형은 이 모델 데이터 분할의 표본 수에 포함하지 않습니다.

| 결과 | 의미 |
|---|---|
| PASS | 관측한 조건과 정답을 충족 |
| FAIL | 검증 가능한 기대·금지 조건 위반 |
| ERROR | 실제 동작을 완료하지 못함; 성공으로 계산하지 않음 |
| PENDING_REVIEW | 자동 검증만으로 의미·동작 전체를 확정할 수 없음 |
| NOT_RUN | 예정됐지만 아직 결과가 없음 |
| SKIP | 실행하지 않은 이유가 있는 항목 |
| UNSUPPORTED | 문서화된 제품 범위 밖인 기능; 실패와 구분 |

제품이 지원한다고 명시한 기능이 없거나 고장 났으면 `FAIL/ERROR`입니다. 미지원은
제품 범위 문서 근거를 첨부한 검토로 확정합니다. 단일 사용자 DB·내부 owner 범위
통과를 실제 다중 사용자 로그인·공유 권한 통과로 표시하지 않습니다.

자동 검사에서는 인용 원문·문자 위치·버전·삭제 상태, 필요한 근거 집합, 금지된 값,
기대 동작 등을 확인합니다. 단어가 포함됐다는 이유로 자연어 답변을 통과시키지 않습니다.
등록한 허용 답변과 전체 문장이 일치하고 인용·필수 근거·동작 검증까지 통과하면 자동으로
확정할 수 있습니다. 숫자의 소수점, 파일명의 점, 부정 표현은 일치 비교에서 지우지 않습니다.
표현 차이가 있는 답변은 필수 사실의 일치·누락과 금지 사실 언급을 자동 표시하되
의미적으로 틀렸다고 단정하지 않고 검토 대기로 둡니다. 독립 검토의 실패 판정을 문자열 일치로 덮어쓰지 않습니다.

현재 평가 버전은 `main-suite-v6`입니다. 질문·입력 원문·수행 단계·기대 결과·분할 등 실행 조건이
같은 중복 사례를 하나로 통합했습니다. 연결 변수·정상/경계 조건·기존 사례 ID는 통합 사례에 보존하며
여러 변수에 연결됐다는 이유로 같은 실행을 반복하지 않습니다. 질문이 같아도 실제 조건이 다르면 남깁니다.
이전 v1/v2 실행을 덮어쓰거나 동일 조건의 공식 비교로 취급하지 않습니다. 기존 실행의 빈 답변을
사후에 만들어 채우지 않습니다. 실제 답변과 자동 비교 결과는 사용자가 새 실행을 요청한 뒤 수집됩니다.

관제실의 **전체 변수·지원 현황 보기 → 질문·예상 답변 보기**에서 실행 전에 합성 사례를
확인할 수 있습니다. 이 조회는 평가를 시작하지 않습니다. 새 실행 결과의 **질문·답변** 탭에는
기준 답변, 실제 답변, 일치·누락·금지 사실 및 자동 검증 범위를 표시합니다.

**메인 화면 → 테스트 데이터셋** 또는 관제실의 **전체 테스트 데이터셋 보기**에서 등록 사례 전체를
조회할 수 있습니다. 메인 화면에는 사례 수와 펼쳐 볼 수 있는 질문 미리보기도 표시합니다.
검색·영역·개발/최종 구분·실행 프로필로 필터링하고, 사례를 선택하면 합성 입력 기록·원문 정답 위치·
수행 단계까지 확인할 수 있습니다. **전체 데이터 내려받기**는 카탈로그와 사례 전체를 JSON으로 제공합니다.
이 데이터는 합성 계획 데이터이며 개인 기록이나 과거 실행 결과를 포함하지 않습니다.
목록과 메인 미리보기에는 같은 질문을 한 번만 표시합니다. 정상·경계 또는 입력 조건이 다른 사례는
질문 안의 **검사 조건** 선택으로 확인합니다. 질문 수와 검사 조건 수를 별도로 표시하며,
검색과 페이지 나누기도 질문 단위로 적용합니다. 조건별 실행과 기존 결과는 그대로 보존합니다.
검사 조건 상세의 **테스트 기억 원문**은 입력 기록을 읽기 쉬운 본문으로 표시합니다.
메인 화면의 **나의 기록 → 테스트 기억 원문**에서도 전체 합성 원문을 검색·열람하고 연결된 검사로 이동할 수 있습니다.
동일 원문은 모아 표시하며 수정 전 버전과 저장·비저장 요청 대화의 출처를 구분합니다.
이 보기는 읽기 전용이며 개인 기록 DB에 삽입하거나 실제 기억 추출·색인·메인 평가를 실행하지 않습니다.
기존 짧은 합성 문장 145개는 `evaluation/main_suite/data/source_records.json`의
`main-source-v1` 원문 데이터로 등록했습니다. 사례의 입력 기록에는 `source_id`, 수정 전 원문에는
`initial_source_id`를 연결하고 저장·비저장 요청 대화도 원문에 연결합니다. 실제 평가는 등록 원문을
읽어 사용하며 사례의 본문·버전·소유자와 다르면 실행 오류로 남깁니다. 개인 기록에는 삽입하지 않습니다.
**나의 기록 → 테스트 기억 원문 → 원문 데이터 전체 내려받기**에서 이 원문 데이터 파일을 받을 수 있습니다.

완료된 실행은 주기적으로 다시 그리지 않습니다. 실행 중에는 변경된 진행 상태만 갱신하며,
열린 사례 상세는 유지합니다. 최신 실제 답변을 다시 읽으려면 **새로고침** 버튼을 누릅니다.
검색 조건·페이지·선택한 사례는 주소에 보존되어 브라우저를 새로고침해도 복원됩니다.

`answer_correct`, 근거 충족 답변 성공률, Recall@8/@20, 완전 근거 검색률, MRR,
nDCG@20, 문맥·인용·동작 정확도, 되물음·보류 precision/recall을 분리합니다.
검색을 관측하지 못한 경우 검색 지표는 0이나 1 대신 미확인입니다.
응답 지연은 p50/p95/p99, 색인 시간은 별도로 기록합니다. RAM은 Python과 평가용
모델 서버의 작업 집합 합계 관측 최댓값이며, GPU 메모리와 구분합니다.

모든 비율에 판정 가능한 표본 수를 표시합니다. 종합 성공률은 예정된 지원 범위 내
시도 중 통과한 비율로 계산하여 오류·미실행·검토 대기가 분모에서 사라지지 않게 합니다.
상위 검색 결과가 원문 단위로 중복되면 첫 순위만 사용합니다.

### 사람 검토와 증거

원본 `cases.jsonl`은 덮어쓰지 않습니다. 별도 JSON 검토 파일에 다음을 작성합니다.

```json
[
  {
    "trial_id": "LC-04.normal.r1",
    "observation_hash": "실행 상세의 정확한 해시",
    "reviewer": "검토자 이름",
    "reason": "원문과 답변의 전체 주장·시간·수치·인용을 대조한 판정 이유",
    "evidence": ["review-evidence/LC-04.txt"],
    "verdict": "PASS",
    "evaluation": {"answer_correct": true, "claims_supported": true}
  }
]
```

증거 파일은 해당 후보 폴더 안에 저장합니다. 실패·다른 원문 해시·이미 끝난 검토는
이 방식으로 덮어쓸 수 없습니다. 카탈로그 동작 검토는 `answer_correct`를 부여할 수 없습니다.
`UNSUPPORTED` 판정에는 `product_scope_reference`가 추가로 필요합니다.

```powershell
./.venv/Scripts/python.exe -m evaluation.main_suite --output .local/main-suite/baseline-001/baseline--baseline --review-file .local/reviews.json
```

이는 실제 모델 호출 없이 검토 이력을 추가하고 보고서를 다시 집계합니다.

## 합격선과 모델 선택

첫 실행은 기준값 수집입니다. 임의의 90%나 95% 합격선을 넣지 않습니다.
실측 결과를 사용자에게 보여준 후 다음 형식의 합격선 파일을 별도 확정합니다.

```text
version: 사용자가 확정한 기준 버전
approved_by: 사용자 확인 내역
minimums:
  grounded_answer_success_rate: 확정한 0~1 값
  answer_correct: 확정한 0~1 값
  complete_evidence_recall: 확정한 0~1 값
```

실제 파일은 위 구조의 JSON이며 `--gates <파일>`로 지정합니다. 미완료·검토 대기·부분
실행·미지원이 남으면 공식 추천하지 않습니다. 비허용 정보 노출·삭제 데이터 노출·허위
인용은 0건이어야 합니다. 검사되지 않은 영역을 노출 0건의 검증 완료로 주장하지 않습니다.

통과 후보는 근거 충족 답변 성공률 → 답변 정확도 → 완전 근거 검색률 순으로 비교합니다.
동일 계열의 반복을 독립 표본으로 취급하지 않고 계열별 paired bootstrap 2,000회,
95% 구간으로 우열을 확인합니다. 구분이 어려우면 p95 지연, 최대 RAM으로 비교합니다.
통과 후보가 없으면 선택 보류입니다. 선택 결과는 앱 기본 설정에 자동 적용되지 않습니다.

## 관제실과 산출물

앱은 기존처럼 `./run_app.ps1 -Evaluation`으로 켭니다. 관제실에서 직접 실행할 수 있으며,
결과가 없어도 계획·카탈로그·실행 프로필을 표시합니다. `GET /api/eval/plan`은 조회 전용입니다.
기존 회귀 비교와 모델 비교는 별도 모드입니다. 모델 비교는 명시한 모델 차이만 허용하고
코드·프롬프트·데이터·환경·검색 조건이 달라지면 공식 비교를 거부합니다.

실행 결과를 관제실에 실시간 표시하려면 실행 명령에 다음을 추가합니다.

```powershell
--publish-to "$env:LOCALAPPDATA/PersonalMemoryAgent/evaluation/evaluation.db"
```

평가 DB만 쓰며 기억 DB는 읽거나 쓰지 않습니다. 질문·답변·상세 원문 조회는 기존의
`PMA_EVALUATION_DETAILS` 설정이 원문 표시의 초기값입니다. 관제실의 **질문·답변 원문 표시**를
선택해 현재 앱 실행 중의 표시 여부를 바꿀 수 있습니다. 원문을 숨기면 목록 미리보기와
상세 답변·근거·처리 기록도 함께 가립니다. 변경 요청은 로그인과 CSRF 검증을 거치며,
환경 설정이나 개인 기억 DB를 수정하거나 평가를 시작하지 않습니다.
증거·원문·검토 해시·재현 명령은 선택한 사례의 상세 영역에서 확인합니다.

### 테스트 사례를 짧게 보고 상세 정보 선택하기

- 목록은 질문과 예상·실제 답변을 짧은 미리보기로 보여주고, 예상 동작과 실제 동작을
  별도 열에 표시합니다. 원문·근거·전체 처리 기록은 목록 응답에 싣지 않습니다.
- 사례 ID나 행을 선택하면 목록 아래 상세 영역이 열립니다. 목록은 그대로 남아 다른
  사례와 번갈아 비교할 수 있습니다. 선택한 사례는 주소에도 반영됩니다.
- **질문·답변 / 예상·실제 동작 / 근거·원문 / 처리 과정** 탭에서 필요한 정보를 선택합니다.
  원문의 줄바꿈과 전체 내용은 상세 영역에서 보존합니다. 처리 과정은 해당 탭을 열 때 조회합니다.
- **예상·실제 동작**에는 기대 동작과 관측 동작, 실패 사유, 예정한 단계와 실제로 수집한
  단계·응답을 구분해 표시합니다. 수집되지 않은 동작을 완료했다고 추정하지 않습니다.
- **상세 닫기**로 목록으로 돌아갑니다. 탭은 방향키·Home·End로도 선택할 수 있습니다.
- 원문 표시 선택은 앱 재시작 시 환경 설정의 초기값으로 돌아갑니다.

### 관제실에서 직접 실행하기

1. 앱을 최신 코드로 재시작하고 **평가 관제실**로 이동합니다.
2. **테스트 실행**에서 핵심 평가·모델 비교·확장 평가·최종 검증 중 범위를 선택합니다.
3. 모델 비교나 최종 검증에서는 등록된 모델을 선택합니다. 모델 비교는 기준 모델과
   다른 후보가 최소 하나 필요합니다. 핵심·확장 평가는 기준 조합을 사용합니다.
4. **테스트 실행** 버튼을 누릅니다. 실행 상태와 결과 선택이 자동 갱신됩니다.
5. 멈추려면 **중단 요청**을 누릅니다. 진행 중인 모델 요청은 즉시 끊지 않으며,
   해당 처리가 끝난 후 평가용 서버를 정리합니다. 완료한 결과는 보존합니다.

화면 접속·새로고침·주기적 상태 조회는 평가를 시작하지 않습니다. 진행 중에는 다른
실행을 시작할 수 없고, 같은 요청의 재전송도 실행을 중복 생성하지 않습니다.
앱을 종료하면 해당 앱에서 시작한 평가에 중단을 요청하며, 다시 열어도 자동 재실행하지 않습니다.
새 실행은 새 폴더를 사용합니다. 중단한 실행을 재개하는 CLI 방법은 위 안내와 같습니다.

기본 모델 목록은 `evaluation/main_suite/data/models.json`입니다. 다른 목록을 등록하려면
앱 실행 전에 `PMA_EVALUATION_MODELS`를 해당 JSON의 절대 경로로 설정합니다.
평가 실행 프로그램은 `PMA_EVALUATION_SERVER`로 지정할 수 있습니다.
화면에서는 등록된 모델만 선택할 수 있고 임의의 파일 경로나 실행 명령을 보낼 수 없습니다.
프로그램이나 모델 파일이 없으면 실행할 수 없으며, 자동 다운로드하지 않습니다.

실행·중단 요청은 기존 로그인, 동일 출처, CSRF 검증을 적용합니다.
API는 `GET /api/eval/execution/options`, `GET /api/eval/execution`,
`POST /api/eval/execution`, `POST /api/eval/execution/{job_id}/cancel`입니다.
평가 실행 정보는 별도 평가 디렉터리의 `execution.json`에 저장합니다.

각 후보 폴더에 `manifest.json`, 불변 `cases.jsonl`, `summary.json`, 한국어 `report.md`,
`evaluation.db`, 사례별 합성 DB와 모델 로그를 보존합니다. 사람 검토는
`adjudications.jsonl`에 증거 해시와 함께 추가됩니다. 전체 비교는 `comparison.json`입니다.

기존 자료 중 모델 대체 구현을 쓴 검색·성능 검사는 모델 품질 수치와 합치지 않습니다.
검색 단계 누락, 생성 오류, 인용 오류, 입력·추출 오류를 분리하고 관측하지 않은
실패 원인은 미확인으로 남깁니다.

### 완료된 평가 검토를 반영한 v4 보완 — 2026-10-21

이 변경은 평가기·제품·오프라인 회귀 검사의 보완입니다. 실제 메인 평가는 실행하지

v3의 수치를 동일 조건 회귀 비교로 취급하지 않습니다.

- 비저장 검사는 기존 기록의 존재가 아니라 해당 대화 전후의 기록 변화와 저장 후보를 검사합니다.

  답변 보류·되물음은 상태만으로 실패를 확정하지 않으며, 등록된 완전한 정답과 일치하지 않으면 검토 대기로 둡니다.

- 승인한 정답의 좁은 명사 종결 표현을 대체 정답에 등록합니다. 숫자·부정·파일명은 정규화하지 않습니다.

  일반 모드·기록 사용 거부·명시적 일반 지식 질문은 이 확인을 수행하지 않습니다.
- 명시한 프로젝트의 근거 범위, 자신의 취향, 역할이 다른 동명이인을 구분합니다.
  앞선 검색에서 원문 인용으로 직접 근거라고 판단한 후보가 후속 선택에서 모두 빠진 경우
  독립 답변 검증을 거치는 복구 경로를 사용합니다. 원문 검증을 생략하지 않습니다.
- ‘인증 토큰 만료’라는 장애 설명과 실제 비밀 토큰 값을 구분합니다.
  추출 형식 오류는 원문·스키마를 사용해 한 번만 다시 시도하며, 반복 실패는 오류로 보존합니다.

`core`와 `compare`에는 독립된 악성 지시·삭제 후 재질문·비동의 저장·내부 owner 검사,
최소/최대 길이 입력의 허용 검사와 긴 Markdown의 무손실·중복 가져오기 검사를 포함합니다.
네 가지 필수 보안 검사는 `final`에서도 반복하되 개발용 안전 검사이며 모델 정확도와
최종 검증용 데이터 비율에서 독립적으로 구분합니다. 모두 확정 통과하지 않으면 공식 추천하지 않습니다.
내부 owner 검사는 실제 다중 사용자 로그인·공유 권한 검증을 뜻하지 않습니다.
대량 기록·동시 작업·장애 복구는 기존 정책대로 명시적으로 요청한 `extended`에서 실행합니다.

현재 카탈로그는 변수 489개, 실행 조건 353개입니다. 핵심 프로필은 178개 조건입니다.
등록된 정상·경계 동작 조건이 연결된 변수는 124개이고, 나머지 365개에는 질문·답변
검사만 연결되어 원본 조건의 미검증 범위를 표시합니다. 이 숫자는 제품 기능 124개의
통과나 전체 명세 구현 완료를 뜻하지 않습니다. 화면 배치, 실제 공유 인증 등 미검증
조건을 답변 하나로 통과 처리하지 않습니다. 계획 화면에서 이 차이를 확인할 수 있습니다.

답변 정확도·검색률·인용률은 관측·판정 가능한 표본에 대한 조건부 수치입니다.
v4의 근거 충족 답변 성공률은 기록된 모델 표본의 실행 오류와 미확정을 분모에 포함하며
성공으로 세지 않습니다. 전체 예정 수에 대한 완료·미실행 수와 종합 통과율도 별도로 표시합니다.
보안 검사 수와 통과 수를 함께 표시하므로 미검사 상태의 노출 0건을 보안 통과로 볼 수 없습니다.

회귀 검사는 `tests/test_evaluation_remediation.py`에 추가했습니다. 기존 평가기·관제실·제품의
오프라인 검사와 함께 실행하며, 실제 모델·개인 DB·평상시 모델 서버는 사용하지 않습니다.

확인 결과: 평가·관제실·대화와 관련된 오프라인 검사 332개, 검색·저장·화면 표현·성능 정책과
관련된 검사 217개가 통과했습니다. 변경한 Python 코드 검사와 화면 스크립트 문법 검사도 통과했습니다.
기존 HTTP 통합 검사 7개는 테스트 클라이언트 응답 대기 문제 때문에 제외했습니다. 인증·CSRF·출처
보호는 별도의 실제 미들웨어 핸들러 검사로 확인했으며, 제외한 HTTP 검사를 통과했다고 표시하지 않습니다.
실제 모델의 답변 개선 정도, 전체 화면의 실제 브라우저 배치, 확장 부하 수치는 아직 재측정하지 않았습니다.

### v5 — 365개 동작 검사 및 HTTP 검사 보완

이전 v4의 답변 외 조건 365개 변수에 모두 실행 가능한 동작 검사를 추가했습니다.
기존 질문·예상 답변·원문은 보존했습니다. 변수 489개 모두 검사 경로가 연결되어 있으며,
추가 동작 검사는 모델 평가와 구분한 `contract_tests` 어댑터를 사용합니다.
계획 조회, 앱 시작, 일반 pytest 수집으로 실제 메인 평가를 실행하지 않습니다.

핵심/비교 프로필에는 534개 조건, 확장에는 573개 조건, 최종 후보 검증에는 505개 조건이
포함됩니다. 대량 DB 및 동시 작업용 추가 검사는 확장 프로필에만 있습니다.
총 718개 등록 조건에는 모델 질문, API/저장소/화면 검사, 지원 밖 기능 거절 검사가 함께 있습니다.
지원 밖 기능 24개 변수는 실제 거절을 확인하고 UNSUPPORTED로 표시하며 기능 구현 성공으로 세지 않습니다.

관제실은 추가 검사 방식·기대 동작·실제 검사별 결과·지원 범위를 표시합니다.
대체 모델 기능 검사는 모델 정확도에서 제외합니다. 정상·경계 파라미터를 공유하는 검사를
서로 다른 모델 품질 표본으로 중복 계산하지 않습니다. 테스트 코드도 비교용 코드 해시에 포함합니다.
이전 버전의 결과를 새 판정으로 덮어쓰거나 비교 가능한 실행으로 취급하지 않습니다.

365개 변수의 검사 함수·정상/경계 파라미터·지원 범위는
[실제 동작 검사 대응표](behavior_test_coverage.md)에 기록했습니다.
HTTP 검사 7개의 대기는 Windows의 테스트 루프 초기화에서 발생한 문제였으며,

실제 브라우저에서 근거 원문, 모바일 레이아웃·키보드, 오류/재시도, 필터 변경,
대화 중단, 색인 대기, 원문 HTML 비실행도 검사합니다.

본 변경의 검사 결과는 오프라인 개발 검증입니다. 실제 메인 평가·실제 생성/임베딩 모델 호출·
개인 DB 재색인·기본 모델 변경은 수행하지 않았습니다.

v5 최종 개발 검증: **관련 회귀 검사 637개 통과, 제외 0개**입니다. 이전에 응답 대기로 제외했던
HTTP 검사 7개도 모두 포함하여 통과했습니다. 별도의 네트워크/개인 DB 차단 환경에서
365개 변수에 연결된 실제 동작 조건 253개를 실행했고 모두 통과했습니다.

코드 검사·화면 스크립트 문법 검사·전체 변수 연결·원문 정답·데이터 분리 검사도 통과했습니다.

### v6 — 완료된 실제 평가의 결함 보완

완료된 v5 평가의 별도 검토를 반영했습니다. [변경 내용과 검증 대응표](v6_review_remediation.md)를 확인할 수 있습니다.
전체 등록 조건은 755개이며 핵심/비교 552개, 확장 592개, 최종 523개 조건입니다. 최종 프로필의 반복 5회는 조건 수와 구분합니다.
추가 일반화 사례 35개는 합성 사용자 3명, 다른 주제·작성 형식, 긴 원문·영어 질문,
무관 기록 추가/제거·순서 변경·실제 수치 변경, 명확화·날짜 변경·다중 근거·긴 대화 흐름을 포함합니다.
개발/최종 원문과 질문이 겹치지 않는지 정적으로 검사하며, 내부 owner 검사와 사용자 작성 방식 일반화를 구분합니다.

owner 프로브의 불리언 검사 결과를 안전하게 표시하고, 실행 후 처리 오류에서도 수집한 관측을 보존합니다.
질문에 필요 없는 배경 설명을 필수 사실에서 분리했으며, 승인 저장 선호의 정답과 주제 전환 질문을 수정했습니다.
작성한 `steps[].expect`가 있는 단계는 마지막 답변과 별도로 판정합니다. 단계 누락이나 앞선 턴의 금지 결과는 `F-TURN`이며,
단계 조건을 작성하지 않은 턴까지 전수 의미 검증이 완료됐다고 표시하지 않습니다.

새 지표에는 Recall@1/5/10, 첫 검색 Recall@8, 반환된 출처의 Precision@8/@20, 문자 기준 추출 사실 보존률이 있습니다.
최종 Recall은 마지막 검색 묶음의 출처 중복 제거 순위로 계산합니다. 여러 재검색의 후보를 이어 붙인 순위가 아닙니다.
Precision은 작성된 `source_relevance`가 있고 반환 출처 모두의 등급이 있을 때만 계산하며, 분모는 K 이내 실제 반환 출처 수입니다.
추출 보존률은 `extraction_facts`의 원문별 필수 문자열이 실제 추출의 의미 필드에 보존됐는지 검사하며 인용 원문 자체는 검사에서 제외합니다.
이는 의미적 Fact Recall이나 전체 추출 정확도를 대신하지 않습니다. 정답 주석이 없으면 새 지표는 미측정입니다.
`requested_retrieval_success`는 근거가 필요한 요청의 검색 생략·오류도 실패로 포함하고 기존 조건부 검색률과 구분합니다.

제품에는 원문 식별자 기반 개인 사실 라우팅, 프로젝트/사람 조건 분리, 원문 구간이 검증되는 선택 재검토,
미해결 명확화 유지, 후속 달력 기간 교체, 비저장 안내, 인용 구간별 부가 주장 검사를 보완했습니다.
추출 요청의 값 타입을 태그별 스키마로 제한하고, 잘린 보조 호출에는 문맥·토큰 예산 안에서 한 번만 재시도하며 실제 단계를 기록합니다.
개선된 실제 모델 정확도·지연은 아직 측정하지 않았습니다. 실제 메인 평가는 사용자 별도 요청 또는 인증된 관제실 실행 버튼으로만 시작합니다.
