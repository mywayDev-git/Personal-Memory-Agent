  저장 대기 시 질문 연속 처리 제한을 기본 비활성화 옵션으로 추가했습니다.

## 실제 CPU 검색 비교

기존 로컬 모델을 전용 CPU 서버에서 실행했습니다. 스레드 4, 생성 문맥 16,384,
임베딩 문맥 8,192, 임베딩 배치 4,096이며 모델·원문·질문은 양쪽에서 같습니다.
후보별 준비 실행 1회 후, 같은 검색 질문을 순서를 바꿔 5회씩 측정했습니다.
각 요청 전 실험 슬롯을 비웠으며 RAM 프롬프트 캐시는 껐습니다.

| 항목 | 현재 기준선 | 요청 내부 토큰 캐시 |
|---|---:|---:|
| 측정 표본 | 5 | 5 |
| 검색 중앙값 | 22.096초 | 22.070초 |
| P95 | 24.675초 | 23.401초 |
| 정답 근거 검색 검사 | 5/5 | 5/5 |
| 토큰 캐시 적중 | 0 | 0 |
| 요청당 모델 HTTP 호출 | 4 | 4 |
| 관측 RAM 최대 | 5,012.13 MiB | 5,086.22 MiB |

중앙값 차이는 약 **0.11%**이며 캐시 적중이 없습니다. 유효한 속도 향상으로 채택하지 않습니다.
개인 DB와 운영 GPU 서버를 유지한 공유 호스트에서 수행했으며,
진단 실행 일부 구간에 합성 브라우저 검사도 진행했습니다. 정식 성능 채택 비교로 사용하지 않습니다.
검색 함수 반환 시간이며 최종 기억 답변·브라우저 체감 시간·GPU 성능을 측정한 결과가 아닙니다.
새 다국어 90문항이나 전체 의미 정확도 평가를 대신하지 않습니다.

[실제 표본·계측·모델 및 소스 해시](../evaluation/response_latency_recheck_cpu_token.json)와
[검증 상태·미실행 항목·재현 명령](../evaluation/response_latency_recheck_verification.json)을 함께 확인할 수 있습니다.
원본 측정 당시 제품·평가기 소스가 측정 중 바뀌지 않았음을 확인했습니다.
원본은 변경하지 않았으며 이후 실행기의 CPU 기본값을 성공한 명시적 설정에 맞춘 변경은 별도입니다.

## 준비 실패와 남은 검증

실패한 준비 시도는 성능 표본에 합치지 않았습니다.

| 시도 | 결과 |
|---|---|
| CPU 001 | 실행 제한에서 전용 포트 연결 거부, 외부 중단; 측정 없음 |
| CPU 002 | 임베딩 서버 시작 중 종료(3221225725); 측정 없음 |
| CPU 003 | 슬롯 초기화 URL이 기존 전송 보안 검사에서 거부됨; 측정 없음 |
| CPU 004 | 전용 슬롯 저장 경로 없이 삭제 API 사용 실패; 측정 없음 |
| CPU 005 | 전용 슬롯 경로를 지정해 위 10개 검색 표본 측정 완료 |

003은 일반 전송 URL 검증을 완화하지 않고, 소유한 실험 서버의 고정 경로와 명시적 쿼리 매개변수로 수정했습니다.
슬롯 초기화 HTTP 요청은 리디렉션을 허용하지 않습니다.

GPU 메모리는 확인 당시 8,192 MiB 중 약 7,848 MiB가 사용 중이었습니다.
현재 정책에 따라 운영 서버를 종료하지 않았고, GPU 비교는 미실행입니다.
다른 후보의 실제 모델 비교, 전체 핵심 사례·다국어 재평가, 최종 조합 20회,
지속 동시 부하의 저장 완료 지연도 **미실행**입니다.
따라서 20% 단축 목표 달성이나 최종 품질 통과를 주장하지 않습니다.

## 사용자가 직접 실행하기

먼저 [후보별 실행·기록 열람·복구 안내](response_latency_recheck.md)를 확인합니다.
저장소 루트에서 다음 명령은 모델을 실행하지 않고 계획만 표시합니다.

```powershell
.\.venv\Scripts\python.exe -m evaluation.latency_recheck
```

이번 작은 CPU 비교를 다시 실행하려면 새 이름을 사용합니다.

```powershell
.\.venv\Scripts\python.exe -m evaluation.latency_recheck --execute --name cpu-token-user-001 --candidates token_cache --cases simple_search --placement cpu --threads 4 --embedding-batch 4096
```

전체 후보 선별은 `--candidates`와 `--cases`를 생략합니다. CPU에서는 오래 걸릴 수 있습니다.
GPU 실행은 여유 메모리가 있을 때 `--placement gpu`로 선택하며 기존 서버를 자동 종료하지 않습니다.
결과는 `.local/latency-recheck/<새 이름>/report.md`와 `verification.json`에 남습니다.
자동 선별 성공만으로 의미 검토나 제품 기본값 변경을 승인하지 않습니다.
