# 원문 의미 보존과 답변 관련성

기억 추출 시 `content`, `predicate`, 인용 원문의 동작을 비교한다. 시작/중단,
합격·성공/불합격·실패, 입사·가입/퇴사·탈퇴, 구매/판매의 명시적 반전과
해당 동작의 부정 변형을 검사한다. 여러 시점의 시작·중단이 함께 있는 원문을
한 상태로 강제하지 않는다. 이 규칙은 제한된 보조 검사이며 일반적인 의미 검증의 대체물이 아니다.

반전이 감지되면 원문으로 한 번 다시 추출한다. 재시도에서도 요약만 틀리고
동작 필드가 원문에 명시적으로 지지되는 경우, 요약은 인용 원문 전체를 그대로
사용한다(`summary_fallback=verbatim_supported_predicate`). 동작까지 잘못됐으면
`EXTRACTION_MEANING_MISMATCH`로 실패하며 공개하지 않는다. 추출 캐시 버전은 3이다.
게시 단계에서도 검사하므로 캐시·직접 게시 경로가 이 검사를 우회하지 못한다.

파생 사실 버전은 10이다. 기존 오추출 기억은 `extraction_meaning_mismatch`와
`review_required`로 표시하고 모델 입력에는 잘못된 요약 대신 원문 근거를 제공한다.
파생 사실 재생성은 원본이나 추출 기억을 수정하지 않으며, 오추출 자체는 별도로 재처리한다.

등록 주제 이름만 입력한 검색이나 명시한 공부·학습 주제가 있는 질문에는 원문에서 그 주제가 확인되는 기록만
관련성 검토에 전달한다. 등록 한영 별칭과 조사를 적용하고 같은 문단의 학습 노트도
보존한다. 다른 문단의 선물 기록 등은 같은 문서에 있다는 이유만으로 포함하지 않는다.
폭넓은 질문이나 주제가 생략된 후속 질문에는 이 제한을 임의 적용하지 않는다.
검색의 관련성 판단에는 등록 별칭을 정규화한 질문을 사용해 표기별 차이를 줄인다.
판정 기록에는 `topic_mismatch`를 남긴다.

답변 생성에서는 관련성 선택에서 제외된 배경을 제거하되 명시적인 반박 근거를
유지한다. 답변 검증은 전체 원문뿐 아니라 검토자가 선택한 정확한 근거 문장에도
동작 반전 검사를 적용한다. 공부 주제와 무관한 인용은 모델이 통과시켜도 관련성을 거절한다.
명시한 주제의 답변에서 의미 검사가 실패하면, 두 번째 초안은 확인된 원문 근거를
그대로 인용해 작성한다. 이 초안도 같은 독립 모델 검증을 통과해야 공개한다.
원문 인용을 검증 통과의 예외로 취급하지 않는다.

재처리 시에는 먼저 SQLite 백업을 만들고 원문으로 추출·검증·임베딩을 준비한다.
`Store.publish(..., replace_memory_ids=...)`는 현재 원문 버전과 기존 기억 ID 집합을
확인한 뒤 하나의 트랜잭션에서 파생 기억을 교체한다. 실패하면 기존 기억을 유지한다.
원본 기록·수정 이력은 바꾸지 않는다. 과거 대화와 동결 근거는 삭제하지 않고
`SOURCE_REPROCESSED`로 표시한다. 이전 요청 캐시, 저장 검색 결과, 인용에서
교체된 기억을 현재 근거로 재사용하지 못하게 한다.

회귀 검사는 `tests/test_meaning_integrity.py`에 있다. 실제 모델 검증은 별도로
원본 보존, 재처리 결과, 한영 검색 일치, 중단 의미 유지, 무관한 사실 배제,
원문 인용 및 답변 검증 결과를 확인한다. 처리 시간은 모델·기록·후보 수에 따라 달라진다.
