# 대화 환경 테스트 카탈로그

## 실행 경계

자동 검증은 세 계층을 구분한다.

1. 정책·저장 계약: 합성 원문과 실제 SQLite를 사용한다. 상태 승격 방지, 원문 인용, 권한, 액션 버전·중복·재시도, 업로드 트랜잭션을 결정적으로 검사한다.
2. 실제 브라우저: production HTML/CSS/JS와 합성 API를 사용한다. 실제 개인 앱에 연결하지 않는다. 입력·버튼·원문·모바일·파일 미리보기를 검증한다. 확대 검사는 200%에 해당하는 축소 레이아웃 뷰포트로 실행한다.
3. 실제 모델: 별도 합성 DB에서 검색·생성·독립 검토를 실행한다. 추출 입력은 손으로 작성한 fixture이며 추출 정확도를 이 결과로 주장하지 않는다. 의미 품질과 자연스러움의 사람 평가는 별도로 남긴다.

NAT source-interpretation 테스트 30개는 모든 상태를 임의로 완료·다음 과정으로 승격하지 않는 경계 검사다. 이 30개 통과를 실제 모델 NAT 30개 통과로 대체하지 않는다.

각 실제 모델 사례는 입력 기록·현재 메시지·이전 맥락·검색 기대·해석 기대·응답 유형 기대·필수 개념·금지 주장·출처·버튼 필드와 실제 응답·인용·성능·오류 코드를 함께 저장한다. 현재 기본 모델 평가는 단일 턴의 사실·검색·거부 경계이며, 다중 턴·버튼 결과는 SQLite/API 및 브라우저 검증으로 보완한다.

## 17개 영역과 검증 범위

| 영역 | 대표 자동 검증 |
|---|---|
| IN 입력 | 업로드 형식·크기·UTF-8·공백·NUL, 질문·날짜 API 검증 |
| EX 추출 | 기존 memory complete·meaning integrity·capture 회귀 |
| ST 저장 | 원문·새 버전·가져오기 원자성·출처 위치 |
| QI 의도 | 라우터·학습 재개 부사·개인 기억 거부 |
| QU 질의 | 기존 검색 표현·오타·부분 조건 변경 |
| RT 검색 | 기존 검색 정확도·설명·다국어·순위 회귀 |
| RR 재선정 | 합성 근거 결합·원문 범위·반대 완료 근거 보존 |
| EV 근거 | 인용의 기록·버전·Unicode 구간·삭제 후 차단 |
| CV 맥락 | 대화별 맥락·버전 충돌·재시작·후속 대상 |
| AG 답변 | 기존 독립 사실 검증·계획과 실행·동명이인·인과 |
| MW 기억 변경 | 후보 승인·정정·중복·휴지통·복원·자동 저장 금지 |
| UI 화면 | production 화면의 데스크톱·모바일·키보드·입력·파일 선택 |
| SEC 보안 | Origin·CSRF·인증·소유자 범위·임의 액션 입력 거절·민감 주제 |
| PF 성능 | 동일 조건 실제 모델 비교, 전체 요청 지연·Python CPU·작업 집합 |
| LC 생명주기 | 저장→검색→인용→수정→삭제→복원, 액션·캐시 무효화 |
| NAT 자연스러운 기억 | 아래 30개 사례의 정책 경계 및 별도 실제 모델 실행 |
| UXR 응답·선택 | 아래 20개 계약과 실제 액션·브라우저 검증 |

정상·경계·오류·다중 기록·시간·맥락·권한·변수 조합·실제 UI·전체 생명주기를 계층별로 매핑한다. 모든 17×10 조합을 독립적으로 실측 완료했다는 의미는 아니다. 미실행 조합은 추가 평가 대상으로 남기며 원문·출처·권한·변경 동작 경계에 우선순위를 둔다.

## 재현 명령

```powershell
./.venv/Scripts/python.exe -m pytest tests -q --basetemp .local/conversation-tests
# playwright가 설치된 환경에서
node tests/conversation_browser.cjs
# 별도 평가 서버의 실제 임베딩 모델 SHA-256을 전달
./.venv/Scripts/python.exe -m evaluation.conversation_eval --output .local/conversation-real-new --embedding-revision <SHA256> --embedding-endpoint http://127.0.0.1:18082/v1/embeddings
```

평가 폴더는 존재하지 않는 새 경로를 사용한다. 개인 DB를 복사·수정·색인하지 않는다. baseline 비교는 `--implementation-root`에 보존한 기준 소스 경로를 지정한다. 상세 결과에는 실제 로드한 소스 해시를 기록한다. 오류·시간 초과는 실패로 포함하고 성공 지연처럼 해석하지 않는다.
