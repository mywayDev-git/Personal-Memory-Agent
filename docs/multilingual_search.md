# 한영 번역·발음·유사어 검색

## 검색 정확도 수정 (2026-10-19)

E01~E10 회귀 수정은 역번역이나 추가 의미 검증 모델 호출 없이 적용한다.
모델 제안은 검토된 어휘 대응과 문맥 검사로 확인한 경우에만 보조 검색에 사용한다.
사전에 없는 번역·유사어·인물 및 장소 표기 변환은 `verification_required`로 보류하며 원본 검색은 계속한다.
이는 미등록 이름을 자동으로 식별한다는 뜻이 아니다. 승인 가능한 표현 범위를 제한하는 정책이다.
검토된 유사어는 0.5, 한영 대응은 0.8로 처리하며 모델이 붙인 종류가 가중치를 결정하지 않는다.
대응 사전을 자동으로 학습하거나 별칭 사전에 합치지 않는다.

등록 기술 명사는 조사·설명 어미가 붙어도 사건 판별에서 보호한다. 질문과 저장용 사실 및
`action_relation`이 같은 보호 규칙을 사용한다. 사실 버전은 9이며 기존 백그라운드
`rebuild_facts()`가 백업 후 50개씩 파생 사실·관계 링크를 재생성한다. 원문·기억 payload·증거·임베딩은
변경하지 않는다. 재생성 대기 중의 구버전 사실은 읽기 시 새 규칙으로 계산하므로 검색에서 빠지지 않는다.
구버전 관계 링크는 새 버전 양쪽 사실이 준비된 후 다시 제공한다.

조사는 검토된 명사에 대해서만 분리하고 원래 접미부를 유지한다. 임의 단어의 끝을 조사로 추측하지 않는다.
식별자 전체 구간과 겹치는 편집, 공백·기호만 남기는 편집을 거절한다. 알려진 인물·장소는
부분 문자열 대신 단어와 조사 경계로 보호한다. 중복은 후보 전체를 검증한 후 병합·정렬하고 상한을 적용한다.
`ignored`에 중복·원문 동등 사유를, `verification`에 검증 방식을 남긴다.

24개 관련성 검토 후보 안에는 원본 단독 융합 상위 8개를 유지한다. 최종 근거 8개는 관련성 판단에 따라
달라질 수 있다. `original_rank`와 `original_candidate_reserved`로 원본 후보 유입을 확인할 수 있다.
`correction_enabled=false`는 지원 모델에 `expand=False`를 전달하고 확장 출력 필드를 스키마에서도 제외한다.
옛 `understand(question, today)` 어댑터는 계속 동작하며 생성 제어 미지원 여부를
`generation_control_supported=false`로 표시하고 생성된 확장은 검색에 쓰지 않는다.

검증 결과와 재현 방법은 [정확도 수정 평가](../evaluation/search_accuracy_results.rst),
원시 집계는 [평가 JSON](../evaluation/search_accuracy_results.json)에 있다.

## 검색 규칙

입력한 질문과 기록은 보존한다. 검색용 표현만 별도로 만들며, 날짜·인물·장소·부정·실행 상태와 최종 관련성 판단은 원문 질문의 의미를 따른다. 등록 별칭은 관련성 검토 질문에도 동일하게 정규화한다. DB 스키마 변경은 필요하지 않다. 파생 사실은 버전 10 규칙으로 재생성한다. 기존 임베딩은 보존하되 오추출을 재처리한 기억의 임베딩은 다시 만든다. 원문 의미 검증과 안전한 재처리는 [meaning_integrity.md](meaning_integrity.md)를 참고한다.

`pma/search_expressions.py`가 Python과 C++ 검색의 단어 경계를 공유한다. 전각 ASCII와 대소문자는 검색용으로 정규화하며 원문 문자 위치는 유지한다. `C`, `C++`, `C#`, `.NET`, `Node.js`를 구분한다. 등록하지 않은 단어의 띄어쓰기를 임의로 합치거나 단어 일부를 일치시키지 않는다.

등록 별칭은 Python/파이썬/파이선, API/에이피아이/에이 피 아이, machine learning/머신러닝/머신 러닝/기계 학습/기계학습, deep learning/딥러닝/딥 러닝/심층 학습/심층학습이다. 긴 표현부터 인식하고 복합 조사는 별도로 처리한다. 같은 개념의 키워드 점수는 한 번만 계산하며 등록 별칭은 직접 일치와 같은 1점이다. 일반 조사·활용 정규화는 기존 0.7점을 유지한다. 의미 검색 문장에서는 조사를 제거하지 않는다.

기술 용어 뒤의 `에서`를 장소로 확정하지 않는다. 방문 기록에서 확인된 장소나 명시적인 이동·방문 표현이 있을 때 장소 필터를 적용한다. 질문의 등록 별칭 안에 있는 `러닝`은 달리기 조건으로 해석하지 않는다.

## 자동 확장

기존 질문 이해 호출에서 선택적인 `expansions`를 얻는다. 실제 로컬 모델의 출력 형식에는 이 필드를 요구하되, 오래된 모델 어댑터가 생략해도 앱은 허용한다. `LocalModels.understand(..., expand=False)`는 평가용으로 확장 생성 지침을 끌 수 있다.

각 항목은 `start`, `end`, `before`, `after`, `kind`를 가지며 최대 4개다. `kind`는 `translation`, `transliteration`, `similar`다. 모델이 제안한 단어를 등록 별칭 사전에 자동으로 추가하지 않는다.

서버는 길이·문자 종류·단어 경계·원문 인용·보호할 인물과 장소·날짜·숫자·부정·상태 및 구조 조건 보존을 검사한다. 번역과 발음 확장은 실제 한영 문자 전환이 있어야 한다. 공통 표현을 뺀 나머지가 같은 언어라면 번역으로 인정하지 않는다. Java/코드는 구체적인 질문 문맥이 있어야 확장한다. 모델의 위치 계산이 틀렸어도 정확한 `before`가 원문에 한 번만 존재하면 그 구간으로 확정하고 `span_source=unique_quote`로 남긴다. 여러 번 등장하면 위치를 추측하지 않는다.

유효한 확장 질문은 최대 2개다. 원문 1개, 오타 교정 최대 1개와 합쳐 최대 4개를 중복 제거 후 일괄 임베딩한다. 등록 별칭을 제외한 모델 번역·발음 후보는 순위 기여 0.8배, 유사어는 0.5배다. 같은 기록·검색 방식은 여러 질문 중 최대 기여만 반영한다. 기존 후보 상한 24개와 최종 8개를 유지한다.

확장은 원문 조건을 통과한 후보 안에서만 수행한다. 확장 형식 오류는 유효한 날짜·인물 분석을 버리지 않으며, 추가 임베딩 실패 시 원문만 재시도한다. 사용자 화면의 ‘원문으로만 다시 검색’(`correction_enabled=false`)은 모델 오타 교정과 생성된 번역·발음·유사어 확장을 모두 사용하지 않는다. 단어 경계와 등록 별칭 정규화는 유지한다.

## API와 화면

기존 응답을 유지하고 선택적인 `query_expansion`을 추가한다. 검색 응답과 대화의 검색 snapshot에 `status`, `original_query`, `edits`, `queries`, `searched`, `reason`, `rejected`를 저장한다. 후보가 없어 실행하지 못한 경우도 실행 여부를 구분한다.

결과별 `search_explanation.query_expansion.retrieval`에는 보조 질문·종류·가중치·방식별 순위·실제 순위 기여 여부·검증 가능한 키워드 구간을 제공한다. `keyword_matches[].match_type=alias`로 등록 별칭을 표시하고 기존 `kind`는 유지한다. 모델 확장 문장 자체는 사실의 증거로 쓰지 않는다. 과거 응답에 새 필드가 없어도 표시된다.

## 빌드와 검증

`python -m evaluation.build_keyword_native --zig <zig.exe 경로> --install`로 C++ 모듈을 만든다. 실행 중인 이전 DLL을 덮어쓰지 않도록 `_keyword_native_expressions`라는 새 이름으로 배치한다. 로더는 공통 단어 경계를 지원하는 버전 2 이상만 사용하고, 구버전만 있으면 Python으로 돌아간다. 새 코드는 앱을 다시 시작한 뒤 적용된다.

`python -m pytest tests -q`는 검색·오타 교정·대화·API 회귀 검사를 실행한다. `tests/multilingual_ui.mjs`는 화면 설명을, `tests/multilingual_browser.cjs`는 실제 브라우저의 발음·별칭·Unicode 강조·오류 복귀를 확인한다. 기존 검색 설명과 오타 보정 화면 검사도 유지한다.

`evaluation/multilingual_cases.py`는 개인 정보 없는 고정된 양성 60개와 오탐 방지 30개 사례를 제공한다. `python -u -m evaluation.multilingual_search`는 실제 로컬 질문 이해·임베딩 모델을 사용해 비교하고 `evaluation/multilingual_results.json`에 사례별 결과를 저장한다. 기준선도 동일한 등록 별칭 처리를 사용하며 모델 확장만 끈다. 원문 질문 이해와 확장 질문 이해 시간을 각각 측정하고 실행 순서를 번갈아 적용한다. 평가는 선택적인 LLM 관련성 검토 **이전**의 상위 8개 검색을 대상으로 하며 답변 정확도 평가는 아니다. 문서 임베딩 생성 시간은 검색 시간에서 제외한다.

실제 측정 요약은 [평가 결과](../evaluation/multilingual_results.rst)에 있다. `--replay evaluation/multilingual_results.json --output .local/multilingual-replay.json`으로 저장된 실제 모델 출력을 재사용해 검색 규칙을 재검사할 수 있다. 이 경우 질문 이해 시간은 보존된 원래 측정값이며 검색 시간만 새로 측정한다.
