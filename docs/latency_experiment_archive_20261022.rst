======================================

보존과 작업 구분
----------------

미커밋 변경을 먼저 원본 ZIP과 별도 Git 백업 브랜치에 보존했다.
ZIP에는 수정 파일의 원본 바이트, 작업 상태, staged/unstaged patch와 파일 해시가
있다. ZIP과 manifest는 주 작업 폴더의 ``.local/experiment-backup-20261022``에 있다.
ignore 대상 개인 DB, 모델 및 가상환경은 백업 커밋이나 푸시에 추가하지 않았다.

* ``codex/backup-latency-compact-identifiers-20261022``:
  보고서 문구 수정 전 작업 상태 전체 백업.
* ``codex/backup-latency-ten-second-20261022``:
  10초 응답 실험의 미추적 코드·테스트·실행 기록 전체 백업.
* ``codex/latency-compact-identifiers``:
  호출 안의 간결한 근거 식별자 실험, CPU 가속 배치 검증 및 보고서.
  남아 있던 변경은 고정된 모델 이름 대신 각 결과의 해시·명세를 참조하는
  보고서 문구 수정이며 별도 커밋으로 보존한다.
* ``codex/latency-ten-second``:
  10초 응답 실험의 병목 분석 코드·오프라인 테스트와 과거 실행 기록.
  분석 구현과 실행 기록은 별도 커밋으로 구분한다.
* ``codex/latency-validated-drafts``:
  검토된 단일 원문 초안과 실행 조건의 과거 체크포인트.
* ``codex/interpretation-reuse``:
  동일 질문·맥락 해석 재사용 실험. 이전 미커밋 변경은 이미 ``31a2493``에

* ``codex/first-response-cpu-gpu``:
  해석 재사용 이후 첫 응답 CPU/GPU 비교와 수동 시험 앱의 작업 계열.
  이번 점검 시 최신 커밋은 ``2badc76``이며 작업 폴더는 깨끗했다.

이번 정리는 과거 커밋을 다시 쓰거나 실험 기능을 제품 기본값으로 병합하지 않는다.
각 작업 브랜치와 백업 브랜치를 원격에 보존한다. 주 작업 폴더의
``codex/response-latency-recheck``는 전환하거나 수정하지 않는다.

과거 실행 기록
--------------

루트의 ``measurement.log``, ``processes-before.json``, ``restored-processes.json``,
``run_isolated.ps1``는 과거 실험 당시 자료이며 이번 정리에서 실행·생성한 자료가 아니다.
로그의 CPU 실행은 실패로 끝났으므로 완료된 CPU/GPU 비교나 품질 통과를 의미하지 않는다.
프로세스 ID와 경로는 당시 로컬 상태다.

``run_isolated.ps1``는 특정 과거 실행의 상태 파일과 일반 모델 서버 PID를
참조하는 일회성 스크립트다. 현행 재현 절차로 사용하지 않는다. 가져오기,
앱 시작, 테스트 수집 및 보고서 조회에서 이 스크립트를 실행하지 않는다.
새 모델 평가나 서버 중단·복원은 별도 사용자 요청 없이 수행하지 않는다.

이번 검증
---------

* compact-identifiers: 병목 분석, 모델 식별자, CPU 배치 오프라인 테스트 10개 통과.
* ten-second: 새 병목 분석 오프라인 테스트 2개 통과.
* 보고서 문구는 결과의 모델 해시·명세를 따르도록 정리했다.
* 실제 모델 실행, 공식 메인 평가, 기존 결과 재측정은 하지 않았다.
* 개인 DB와 일반 모델 서버는 변경하지 않았다.
