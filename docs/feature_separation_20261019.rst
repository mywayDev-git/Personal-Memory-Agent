분리 범위
---------

* 검색 설명·오타 보정: 검색/답변 API의 검색 표현 보정, 조건·순위·근거 설명,
  인물 동반 관계 및 관련성 검토를 공통 기반으로 구성했다. 대화 API의 보정
  전달과 요청 멱등성 테스트는 실제 연결이 도입되는 대화 통합 단계에 둔다.
* 기억 저장: 승인 후보, 소유권/출처, 중복·충돌 검토, 저장·보관·관리 API,
  기존 대화 화면에서의 저장 연결과 승인된 표현 선호를 포함한다.
* 디자인: 공통 색상과 아카이브 레이아웃을 분리했다. 대화 DOM 변경은 그것을
  사용하는 대화 스크립트와 함께 통합 단계에 두어 실행 가능성을 유지했다.
* 대화 통합: 라우팅, 문맥/마이그레이션, 인용 API, 답변 검토·표시,
  대화 화면 및 시간 제한 공통 도구를 함께 배치했다.
* CPU/GPU: 실행 옵션, 시작 검사, 모델 차례 양보, 취소/대기와 처리 지표.
* DB: 근거 일괄 조회, 제한된 벡터 캐시 및 검색 정규화 재사용.
* C++: 선택적 네이티브 검색, 빌드·평가 도구 및 Python 동등성 검사.
* 한영 검색: 등록 별칭, 공유 토큰 경계, 모델 확장, 검색 가중치와 설명 UI,
  관련 테스트·문서·평가 자료를 마지막 커밋으로 분리했다.

검증 결과
---------

각 단계의 정확한 파일 구성을 다시 배치한 뒤 전체 pytest를 실행했다.
임시 DB를 사용했으며 운영 DB나 실제 모델 서버는 사용하지 않았다.

* 백업 원본: 253 passed.
* 검색 설명·오타 보정: 32 passed.
* 기억 저장: 90 passed.
* 디자인: 90 passed.
* 대화 통합: 163 passed.
* CPU/GPU 실행: 184 passed.
* DB 최적화: 190 passed.
* C++ 검색 / 한영 검색 이전: 200 passed.
* 한영 검색 포함 전체: 253 passed.

대부분의 단계에 httpx 관련 기존 사용 중단 예정 경고 1건이 있다.
처음 테스트를 실행할 때 sandbox 임시 폴더 권한 오류가 발생하여 저장소 내의
별도 임시 경로를 지정하고 테스트 실행 권한을 조정했다. 기능별 재구성 도중
발견한 의존성 오류는 수정 후 위 결과로 재검증했다.

모든 단계에서 해당 JS 파일의 문법, 오타 보정 화면 로직, Unicode 강조 로직을
검사했고, 기억 저장 도입 이후에는 빠른 저장 3개 흐름도 검사했다.
최종 상태에서 실제 headless Chrome으로 다음을 추가 검증했다.

* 한영 검색: 발음·별칭 표시, Unicode 강조, 오류 시 원문 검색, 모호한 표현,
  HTML 문자열의 비실행 표시.
* 검색 감사 화면: 처리 단계, 시도 이력, 제한, 과거 응답, 삭제·변경된 원문.
* 한영 설명 UI: 번역·발음·유사어와 원문 구간, fallback, 과거 응답 호환.

한영 검색 이전의 C++ 모듈은 기존 바이너리를 덮어쓰지 않고
``.local/native-pre-multilingual``에 별도 빌드하여 Python과 결과 동등성을
검증했다. 이전 브랜치는 새 다국어 토크나이저 바이너리를 자동 사용하지 않는다.
호환 바이너리가 없으면 Python으로 돌아가며, 필요한 경우 해당 브랜치에서
빌드 도구를 사용하여 별도 설치할 수 있다.

새 실제 LLM 정확도 평가, 장시간 성능 재측정, 모든 화면의 수동 검사는 하지
않았다. 기존 평가 파일은 과거 결과로 보존했으며 이번 실행 결과로 간주하지 않는다.
실행 중인 앱과 모델 서버를 재시작하지 않았다.
