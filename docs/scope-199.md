전체 원문 조회 연결 수정

V2는 선택한 자료함을 먼저 불러와 실제 접근 가능한 원문 수를 LLM에 전달한다. 가상 자료함에서는 질문 예시를 고르지 않아도 개발용·확인용 구분 없이 sources.json의 전체 199개를 검색한다. 예시 선택은 검색 범위를 제한하지 않는다.

가상 자료함을 선택했을 때 개인 자료함의 최근 기록을 원문 후보로 전달하던 연결을 제거했다. 최초 읽기 전용 검색은 의도 분류와 독립적으로 수행한다. 검색 결과가 비는 짧은 후속 입력은 이전 사용자 질문을 함께 조회한다. 이전 AI 답변을 사실 근거로 사용하지 않는다.

정의문만 높은 검색 점수를 받아 같은 제목의 담당자 기록이 빠지던 경우에는 관련 원문을 함께 읽는다. 전체 199개가 검색 대상이며, 모델 입력에는 검색한 구간과 관련 원문을 제한된 수로 전달한다. 199개 전문을 한 번의 LLM 입력에 넣는 구조는 아니다.

원문을 읽고 내리는 최종 답변 상태로 사용자 안내와 대기 작업 상태를 갱신한다. 같은 사건에 다른 완료 담당자가 적힌 조건 변형 원문들이 함께 검색되면 차이를 밝히고 각각 인용한다. 정보가 확인되지 않으면 한국어 확인 불가 안내를 표시하고 관련 없는 인용을 붙이지 않는다.

과거 잘못된 읽기 전용 응답 캐시는 새 조회 경로에서 다시 처리한다. 이미 생성된 변경 초안과 실제 기록 변경의 실행 영수증은 재사용해 중복 실행을 방지한다.

검증 명령:

    node --test tests/scope-199.test.cjs
    node tools/test-local-scope-199.cjs

기존의 잘못된 AI 답변이 있는 대화에서 회복하는 추가 검사는 PMA_STALE_ONLY=1로 실행한다. 실제 로컬 Qwen3.5 4B Q4를 사용하고 별도 SQLite DB에서 검증한다. 원본 199개 파일의 해시와 개인 기록의 변경이 없음을 확인한다.
