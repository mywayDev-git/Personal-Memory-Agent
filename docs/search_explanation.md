# 기록별 검색 설명과 선택 정책

검색 결과에는 `search_explanation`, 검색 응답에는 `keyword_terms`와 `search_audit`를 추가한다. 기존 필드는 유지하며 이전 대화에 설명 정보가 없으면 설명 영역을 생략한다. 별도 DB 마이그레이션이나 임베딩 재생성은 필요하지 않다.

## 검색과 표시

- 질문 원문과 검색용 질문을 구분한다. 재구성된 질문은 대화 해석 또는 추가 검색임을 명시한다. 모델의 내부 추론을 노출하거나 추측하지 않는다.
- 실제 필터를 통과한 기록에 사건 종류, 장소, 인물, 사건 기간, 거리, 대상, 상태, 본인 조건을 표시한다. 원문 확인이 필요한 인물 정보는 조건 확정으로 표시하지 않는다.
- 키워드 검색은 원문과 추출된 기억을 각각 단어 단위로 검사한다. 단어 내부의 부분 문자열(예: `수` → `민수는`)은 일치로 처리하지 않는다. 원형 그대로 일치하면 키워드당 1점, 정규화 일치만 있으면 0.7점이다. 같은 키워드의 반복 등장이나 두 필드의 중복 일치는 점수를 중복 가산하지 않는다. `수 있나요`·`수 없다`처럼 가능 여부를 나타내는 `수`는 검색어에서 제외하며, 독립된 한 글자 검색어는 유지한다.
- 한국어 정규화는 제한된 조사 목록과 명시적인 활용형 사전을 사용한다. 한 글자 조사 제거는 말뭉치에서 확인되는 어근에 한정한다. 완전한 형태소 분석기가 아니며 부정 표현을 제거하지 않는다.
- 의미 검색은 정규화 벡터 내적으로 후보를 찾는다. 유사도는 사실 정확도나 확률이 아니다. 키워드·의미 검색은 각각 상위 20개를 사용한다. 기존 구조 조건 후보 경로도 별도 태그로 표시한다.
- 실제 사용된 방식과 방식별 순위, 통합 순위를 제공한다. 키워드 일치 구간은 원문 코드 포인트 위치와 인용문을 함께 검증한 뒤 노란색으로 표시한다. 추출된 기억에만 일치하면 원문을 강조하지 않는다. 답변 인용 근거는 초록색과 별도 라벨로 구분한다.

## 최종 선택

- 기존 순위 합산 `1 / (60 + 순위)`, 역할 참고 가점과 구조 가점은 유지한다. 검색당 통합 후보 상한은 24개다.
- 모델 관련성 검토가 적용되는 기존 질문 경로에서는 4개씩 모든 후보를 검토하고, 묶음 사이에서 8개로 조기 절단하지 않는다. 분류는 직접 답변 근거, 배경 정보, 반박 근거, 관련성 부족이다. 관련 후보의 인용문이 실제 원문에 없으면 선택하지 않는다. 분류는 AI의 관련성 판단이며 최종 답변 검증과 구분한다.
- 관련성 분류가 있으면 직접 답변·반박 근거에 통합 점수의 1.4배, 배경 정보에 0.8배를 적용한다. 동일 원문이면서 이미 확보한 사건 종류·상태의 추가 기억에는 0.55배를 적용한다. 동일 기억 ID는 가장 높은 검색 점수를 유지한다. 동점은 내용·기록 ID·기억 ID 순으로 안정적으로 정렬한다.
- 일반 검색은 최종 8개를 반환한다. 자동 대화는 검색별 최대 24개 후보를 유지하고 최대 3회 검색 결과를 합쳐 8개를 선택한다. 추가 검색도 최초 독립 검색 질문을 기준으로 관련성을 판단한다. 최신·변화·비교 질문은 사건 날짜 내림차순을 유지하며 날짜 미상은 뒤에 둔다.
- 후보 선택, 개수 제한, 모델 관련성 판단, 최종 답변 인용 여부를 따로 기록한다. 선택됐다는 이유만으로 답변에 인용됐다고 표시하지 않는다. 모델이 상세 사유를 제공하지 않는 기존 경로는 미수집임을 표시한다.

## 저장과 제한

- 선택된 기록의 설명은 기존 원문 버전·삭제 연동을 따르는 근거 데이터에 저장한다. 선택되지 않은 기록은 ID, 버전, 조건 통과 여부, 방식, 순위, 결정 코드만 남기고 원문·제목·인용문을 복제하지 않는다.
- 제외된 원문은 사용자가 열 때 인증된 기존 기록 API로 조회한다. 버전이 달라졌거나 삭제된 경우 검색 당시 원문처럼 표시하지 않는다.
- 조건 제외 상세는 최대 100개이며 전체 제외 수와 생략 여부를 표시한다. 통합 후보 24개 밖의 기록은 개수 제한으로 제외된 수를 표시한다. 현재는 전체 제외 기록 페이지 탐색을 제공하지 않는다.
- 진단 모드와 무관하게 사용자용 설명을 생성한다. 진단 이벤트도 변경된 선택 수와 실제 결정에 맞춘다.

## 검증

### 질문 의도 및 사실 검증 보강

- 명시적인 대상에 대한 넓은 설명 요청은 관계·직업 질문으로 좁히지 않는다. 검색용 질문을 답변 검증 질문에 붙이지 않으며, 대명사 해석은 기존 대화 맥락 해석 단계에서 수행한다.
- 대화 검증은 원문 문장별 `span_id`와 답변 `index`를 받는다. 서버가 각각 정확한 원문 인용과 답변 문장으로 변환한 다음 기존 인용·의미 검증 계약을 적용한다. 다른 기록의 구간, 답변에서 인용하지 않은 근거, 중복·누락된 항목은 거절한다.
- 사실 검증에는 `display`를 전달하지 않는다. 사실 통과 후 표시만 별도로 검증하며, 최대 10초의 선택적 작업 예산과 응답 저장 여유를 둔다. 표시 실패·시간 부족 시 일반 문장으로 표시한다. 날짜가 필요한 질문의 사실 검증은 유지한다.
- 검증 형식 오류는 같은 답변을 재검증하고, 내용 오류는 답변을 재작성한다. 검증은 최대 두 번이며 전체 요청 시간 제한을 유지한다. 부분 사실을 남길 때도 반대 근거를 포함한 전체 근거로 재검증한다.
- 일반 답변과 대화 답변은 동일한 부정·인과·명령·시점 의미 검증 지침을 공유한다. 대화에서는 모델이 승인하더라도 원문에 없는 명시적 인과 주장과 `하기로 하지 않았다`를 `하지 않기로 결정했다`로 바꾸는 확인 가능한 변형을 추가로 거절한다.
- 일반 질문에는 저장 시각을 생성 근거로 제공하지 않는다. 문서 기준 시각은 상대 날짜 해석이 필요한 원문에만 제공한다. 명시적으로 기록 시점을 묻는 경우는 제외한다.
- 파생 사실 버전 8은 원문과 집중된 사건 문장 모두에서 확인한 동행자를 `participants`로 남긴다. 넓은 검색에서 원문에 이름이 있지만 역할이 불명확한 기록은 `needs_review` 후보로 유지한다. 부정·추천·가정 표현은 동행자로 확정하지 않는다. 기존 백업·점진 재구축 경로로 반영하며 원문과 임베딩은 변경하지 않는다.

### 단계별 탈락 및 답변 미사용 설명

- 새 검색의 `search_audit.candidates[].stages`는 `conditions`, `selection`, `answer` 상태를 구분한다. 미실행은 `not_run`, 원문 확인이 필요한 조건은 `needs_review`로 남긴다. 실패 조건에는 `expected`로 요청 조건만 저장하고 제외 원문의 실제 값은 복제하지 않는다.
- 메시지 snapshot의 `answer_audit`에는 초안·재작성별 인용 ID, 검증 상태와 사유 코드, 최종 기록별 사용 결과를 저장한다. 초안 내용, 검증 모델의 자유 서술, 원문 인용은 복제하지 않는다. 추가 모델 호출은 없다.
- `draft_not_cited`는 최종 초안의 미인용 사실이며 모델의 미선택 동기를 뜻하지 않는다. `citation_removed`는 통과한 검증에서 인용이 제거된 경우, `answer_rejected`는 답변 전체 검증이 실패한 경우다. 후자는 기록 자체의 오류가 아니라 공통 답변 실패로 표시한다.
- 기존 대화에는 새 사유를 추정해 넣지 않는다. 기록 확인은 기존 버전 검사와 삭제 처리를 유지한다.
- `tests/test_answer_audit.py`와 검색 테스트는 검증 실패·인용 제거·재작성·개수 제한·메타데이터 연결을 검증한다. `tests/search_audit_browser.cjs`는 Playwright와 Chrome으로 실제 화면, 과거 데이터, 삭제·변경 기록을 검증한다. 요청을 로컬 fixture 파일로 대체하므로 서버나 개인 데이터가 필요하지 않다.

`tests/test_search_explain.py`는 한국어 조사·활용형, 원문 위치, 요약 전용 일치, 날짜 미상, 중복, 뒤쪽 후보, 반박 근거, 허위 인용 차단, 전역 개수 제한, 날짜 정렬을 검증한다. `tests/search_explain_ui.mjs`는 실제 화면에서 질문·조건·선택 상태와 강조 색상 구분을 검증한다. UI 검증은 개인 데이터 없는 `evaluation.chat_ui_server`를 사용한다. 실제 로컬 모델의 검색 정확도는 별도 실제 데이터 평가가 필요하다.
