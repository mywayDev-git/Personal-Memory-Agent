# Plant Thought

현재 작업한 화면과 기억 처리 로직입니다. 화면의 배치·색상·글꼴은 유지하고 기존 버튼 스타일로 상황별 조작을 추가했습니다.

## 실행

저장소 루트에서 node plant-thought/start.cjs를 실행합니다.

화면: http://127.0.0.1:4180/
모델 관리: http://127.0.0.1:4321/baseline
HTML 파일을 직접 여는 대신 위 주소를 사용합니다. 실행 창에서 Ctrl+C를 누르면 이번 서버와 모델을 종료합니다.

Node.js의 node:sqlite 지원과 C:\llama.cpp\llama-server.exe가 필요합니다. 모델이 없다면 저장소 루트의 node setup-models.cjs로 준비합니다. 모델은 저장소 .models 또는 PLANT_MODEL_DIR에서 읽습니다. 별도 4319 서버가 설치 모델 폴더를 알려 주면 모델 파일만 재사용할 수 있습니다. 앱 모델 포트는 18501/18502입니다.

개인 기록·작업 상태·모델 로그는 plant-thought/.local/baseline에 저장하고 Git에서 제외합니다. 기존 워크벤치 저장소와 분리합니다. 로컬에서 시험한 DB, 모델 파일, 실행 보고서는 커밋하지 않습니다.

## 반영한 기능

- 기억 조회·저장 의도 구분, 명시적 저장 요청 처리
- 모호한 대상의 확인 질문과 실제 기록 후보 버튼
- 상세 기록의 수정하기, 변경 전·후, 수정 반영·취소
- 상세 기록의 기억 삭제, 삭제 전 확인·취소와 같은 작업의 결과 확인·재시도
- 대화에서 연 원문의 사색 대화로 돌아가기, 보관소에서 연 기록의 보관소로 돌아가기
- 대화에서만 정정한 내용과 저장 원문 수정 구분
- 작업 식별자로 저장 결과 확인·재시도, 동일 작업 중복 저장 방지
- 참고 기록 열기, 일부 검색 결과에서 추가 조회
- 삭제·변경된 근거 기록의 문맥·인용 재사용 검사

대화 화면은 기존 M1 / Top-K 3을 사용합니다. 검색 경로를 G1으로 바꾸는 변경은 이번 작업에 포함하지 않았습니다.

## 가상 원문과 시나리오

서버 실행 후 별도 창에서 아래 명령을 순서대로 실행하면 가상 기록을 넣습니다. 시험 자료를 실제 개인 기록과 함께 넣고 싶을 때만 실행하세요.

    node plant-thought/load-test-records.cjs
    node plant-thought/load-all-test-records.cjs

첫 명령은 기본 기록 10개, 두 번째는 40개 사례의 원문 37종과 추가 동명이인 예시 2종을 처리합니다. 새 저장소에서는 중복 1종을 재사용해 총 48개입니다. 같은 날짜·본문을 재사용하고 원문 검증 결과를 로컬 보고서에 남깁니다.

자료가 함께 있어 “근거 없음/있음”, “정정/충돌” 등 독립 조건을 동시에 평가할 수 없습니다. 삭제·권한 회수 사례도 열람용 가상 원문으로 적재하며 그 상태를 실제 적용하지 않습니다. 질문·예상 답변·앞 대화는 저장 원문에 섞지 않습니다.

자동 검사는 화면 연결 11개와 서버 처리 로직 23개, 총 34개입니다. 삭제 확인·취소·동일 작업 재시도·버전 보호와 원문에서 동일 대화로 돌아가는 동작을 포함합니다. 실제 모델로 저장·수정·취소와 중복 저장 방지, 원문 적재를 별도 확인했고 실제 화면에서 대화 복귀와 임시 기억 삭제를 확인했습니다. 40개 실제 모델 시나리오 전체 통과를 의미하지 않습니다.

- 전체 적재 후 “민수랑 어디 갔었지?”는 실제 모델에서 일반 조회로 분류되고 후보 버튼이 반환되지 않았습니다. 동명이인 확인 처리는 보완이 남았습니다.
- 실제 로그인·공유 권한 회수는 미구현입니다. 현재 로컬 소유자·삭제 여부·버전을 확인합니다.
- 일반 화면에 시각·실패·검색 후보 주입 기능은 없습니다. 해당 시험은 독립 환경이 필요합니다.
- 대화 목록과 문맥은 페이지 메모리에 있어 새로고침하면 초기화되며 저장한 기록은 유지됩니다.
