Plant Thought 문제 보완 후 재검증
2026-11-13 / Asia/Seoul

수정 사항
1. 짧은 경험 진술의 의도 분류에서 과거 기록 목록을 분리하고 저장 확인으로 연결.
2. 저장된 인물 색인과 원문 소속·관계 단서로 후보를 생성. 선택 범위만 좁히고 사람을 영구 병합하지 않음.
3. 명시적 동일인 연결 근거가 없으면 확인 불가 안내. 명시적 연결 문장이 있으면 근거 조회로 처리.
4. 사용자 대화 문맥을 분류와 조회에 전달하고 접근 가능한 근거만 재사용.
5. 고유 출처 수로 참고 기록을 세며, 근거 없는 감정 응답은 현재 이야기 기반으로 표시.
6. 근거 없는 내부 후보 ID 노출을 제거하고 선택 완료한 후보 버튼을 정리.
7. 재시도 성공 뒤 제출했던 입력만 지우며 새 초안은 보존.
8. 감정 공유의 실패·준비 부족 단정을 피하고 조언 요청이 없으면 공감으로 응답.
9. 삭제 후 상태 문구와 복구용 원문·백업 보존 안내를 명확히 표시.

실제 재검증
- 민수랑 부산 갔어. → 기록하기 / 취소.
- 같은 대화에서 취소 → 기록 추가 없음.
- 새 대화의 민수랑 어디 갔었지? → 출처 기반 후보 4개.
- 학교 맥락 선택 → 부산 해운대만 답변, 완료된 후보 버튼 제거.
- 동일인 판단 → 명시적인 연결 근거가 없어 확인할 수 없다고 안내.
- 날짜가 명확한 기본 조회 → 중앙도서관·발표 자료 정리.
- 학교 맥락이 있는 후속 질문 → 불필요한 재확인 없이 해당 기록으로 범위 제한.
- 제주 숙소 질문 → 확인 불가, 숙소 창작 없음.
- 감정 공유 → 공감 한 문장, 현재 이야기 바탕 · 참고 기록 없음, 자동 저장 없음.

자동 검사: 44개 통과. 실제 모델 API 확인: 8개 통과.
기존 원문·버전 유지: true / 활성 기록: 48개.

시나리오 유지
기존 40개 기준·원문·기대 동작을 유지한다. 독립 사례는 자료·시각·오류 조건을 별도로 준비한다.
이번 대표 입력 재검증을 40개 독립 사례 전체 평가로 해석하지 않는다.

보안 범위
현재 로컬 앱의 출처·토큰·경로 검사 8개가 예상대로 동작했다.
계정별 인증·공유 권한은 미지원이며 로컬 조회 API는 사용자 로그인 인증을 제공하지 않는다.
삭제는 보관소·검색 제외 방식이다. 복구용 원문·백업은 남으며 물리적 완전 삭제는 별도 정책이 필요하다.

테스트 시나리오 순서
새 대화 기본 조회 → 새 대화 동명이인·후보 선택 → 새 대화 동일인 판단 → 새 대화 없는 정보 → 새 대화 경험 진술 → 같은 대화 취소 → 새 대화 감정 공유.
추가 회귀 검사: 날짜 명확한 조회, 기존 문맥의 후속 질문, 재시도 입력 보존, 수정·삭제·대화 복귀.
