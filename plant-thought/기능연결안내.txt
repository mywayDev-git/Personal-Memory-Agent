Plant Thought 기능 연결

실행
1. 이 폴더의 start-local.ps1을 PowerShell에서 실행합니다.
2. http://127.0.0.1:4180/ 에 접속합니다.
3. 모델 준비가 필요하면 http://127.0.0.1:4321/baseline 에서 준비합니다.
   생성 모델: Qwen3.5 4B Q4_K_M / 임베딩: Qwen3 Embedding 0.6B Q8_0
   HTML 파일을 더블클릭하는 방식에서는 기능 서버에 연결되지 않습니다.
4. 실행 창에서 Ctrl+C를 누르면 이번에 시작한 서버와 모델을 종료합니다.

색상, 글꼴, 여백, 테두리, 화면 배치 등 원래 CSS는 변경하지 않았습니다.
실제로 저장된 내용과 처리 상태에 맞춰 문구와 목록 내용은 달라집니다.

연결한 기능
- 홈에서 새 대화 시작, 실제 로컬 AI 답변, 최근 대화 문맥 전달
- 대화 목록 전환, 새 대화별 문맥 분리
- 기록 저장 전 확인/취소, 중복 기록 확인, 일정 날짜·시각 확인
- 명시적인 저장 요청은 불필요한 재확인 없이 저장하고, 단순한 이야기는 저장 여부 확인
- 동명이인·대상이 애매하면 실제 기록에 있는 후보 버튼과 추가 질문 제공
- 기록 상세의 수정하기 → 변경 전·후 비교 → 수정 반영/취소
- 기록 상세의 기억 삭제 → 삭제하기/취소 확인, 처리 결과 확인과 같은 작업 재시도
- 대화에서 연 원문은 사색 대화로 돌아가기, 보관소에서 연 기록은 보관소로 돌아가기
- 이번 대화에서만 바로잡은 내용과 원본 기록 수정 구분
- 저장 결과가 불확실하면 상태 확인 후 같은 작업으로 다시 시도, 중복 저장 방지
- 근거 기록 열기, 일부만 검색한 경우 추가로 찾아보기
- 변경·삭제된 근거를 이전 답변과 대화 문맥에서 재사용하지 않도록 확인
- 기록의 영구 저장 및 다시 열 때 복원, 최근 기록, 날짜별 목록, 시간순 보기
- 원문 일치 검색, 실제 백엔드 검색 결과를 이용한 의미 유사 검색
- 답변별 참고 기록 접기/펼치기
- 기존 설정 체크박스 동작 및 브라우저별 설정 저장
  의미 유사 검색 설정은 보관소 검색에 적용합니다.

현재 index.html에 화면/조작 요소가 없어 추가하지 않은 기능
- 마음 성좌도/사건 그래프 시각화
- 모델 다운로드·선택·실행 관리 (별도 /baseline 관리 화면 이용)
- G1 등 검색 방식 비교 및 평가 워크벤치 (별도 /baseline 이용)
- 요약 기억 재생성·삭제 관리 (별도 /summary 이용)
- 파일 내보내기 버튼
- 감정·태그 수동 선택 (작성 화면에서 제거된 상태 유지)

연결할 백엔드 기능이 없는 화면
- 로그인·회원가입: 브랜치에 계정 인증 서버가 없어 기존 시연 상태 유지
- 하단 서비스 안내·개인정보 보호·도움말: 기존 안내 상태 유지

저장 위치와 서버
- 이번 화면의 기록은 ./.local/baseline 에 저장합니다.
- 기존 4319번 서버와 그 서버의 개인 기록은 변경하지 않습니다.
- 4321번: 이번 화면용 브랜치 서버 / 4180번: 화면 서버
- 기존 4319번 서버가 알려주는 설치된 모델 폴더가 있으면 모델 파일만 읽어 사용합니다.
  모델을 새로 다운로드하거나 기존 모델 파일을 수정하지 않습니다.
- 생성/임베딩 모델은 별도 포트 18501/18502에서 실행합니다.
  기존 모델 서버도 실행 중이면 메모리를 더 사용합니다.
- 모델 폴더를 직접 지정하려면 실행 전에 PLANT_MODEL_DIR 환경변수를 지정합니다.
- 대화 목록과 문맥은 브랜치와 같이 페이지 메모리에 유지되며 새로고침하면 초기화됩니다.
  저장한 기록과 브라우저 설정은 유지됩니다.

검증
- node --test memory.test.cjs conversation-ux.test.cjs
- 원래 CSS 동일 여부, 저장/복원/중복/저장 실패, 대화 문맥, 일정 확인,
  검색 결과 연결, 설정 저장, 로컬 요청 전달을 분리된 시험 데이터로 확인합니다.
- 실제 모델 응답의 의미 정확도를 보장하는 검사는 아닙니다.
- 자동 검사 34개 통과: 화면 연결·대화 복귀·삭제 확인 11개와 서버 처리 로직 23개.
- 실제 모델로 질문 답변, 수정 초안/취소, 임시 기록 저장·중복 방지·수정 반영을 확인했습니다.
  임시 검증 기록은 정리했고 기존 테스트 기록 10개의 내용·버전은 유지했습니다.
- 화면에서 수정하기, 변경 전·후, 수정 반영/취소 버튼과 취소 동작을 확인했습니다.
- 대화기억_UX_테스트사례.json의 40개는 입력·기대 동작 명세입니다.
  40개 전체를 실제 모델로 시험 완료했다는 뜻은 아닙니다.
- 실제 계정/공유 권한 체계는 미구현입니다. 현재 로컬 소유자, 삭제 여부, 기록 버전을 확인합니다.
- 동명이인·별칭·의미 분류는 모델이 판단하므로 오판 가능성이 있습니다.
  후보 ID·원문 교체 구간·버전 검증과 저장 전 미리보기를 함께 적용합니다.

전체 가상 원문 적재 (이후 사용자 요청으로 실행)
- 40개 사례의 원문 37종과 대화의 동명이인 예시 2종을 실제 보관소에 넣었습니다.
- 기존 원문 1종 재사용, 신규 38개 추가로 보관소 총 48개입니다. 기존 10개는 유지했습니다.
- 제목의 [테스트 UX T번호]로 사례를 구분합니다. 기존 원문 재사용 시 기존 제목을 유지합니다.
- 보관소에서 '테스트'를 검색하면 기존·추가 가상 기록을 찾을 수 있습니다.
- 가상기록_전체적재_질문안내.txt에 질문과 필요한 앞 대화를 정리했습니다.
- all-test-records-load-report.json에 원문별 저장 결과와 검증 결과가 있습니다.
- 자료를 함께 넣었으므로 독립 사례별 기대 결과와 다를 수 있습니다.
  삭제·권한 회수 원문도 열람용 자료로 저장했으며, 접근 상태·오류·시각 조건은 재현하지 않습니다.
- 원래 사례 명세의 미실행 상태는 유지합니다. 데이터 적재는 평가 통과를 뜻하지 않습니다.
- 전체 적재 후 보관소에서 '테스트' 검색 결과 48건과 동명이인 원문 열기를 확인했습니다.
- 전체 적재 후 실제 모델에 '민수랑 어디 갔었지?'를 입력했을 때 question으로 분류되고
  후보 선택은 반환되지 않았습니다. 동명이인 확인을 안정적으로 유도하는 처리는 보완이 남아 있습니다.
  실제 결과는 all-test-homonym-check.json에 별도로 보관했습니다.
