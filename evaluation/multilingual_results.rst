한영 번역·발음·유사어 검색 평가
================================

2026-10-19, 합성 문서 216개와 고정 질문 90개로 평가했다.
실제 로컬 Qwen3 질문 이해 모델과 BGE-M3 임베딩을 사용했다.
개인 DB는 읽거나 수정하지 않았다.

결과
----

* 일반 검색 60개: Precision@8 83.96% → 92.50%, Recall@8 71.46% → 80.00%.
* 오탐 방지 30개: Precision@8과 Recall@8 모두 100% → 100%.
* Python, API, machine learning의 등록 별칭 단일 질문은 순서와 점수가 동일했다.
* 90개 모두 측정을 완료했고 실행 오류는 없었다.

일반 검색의 질문 해석·검색 평균은 2.27초 → 3.67초,
오탐 방지 사례는 2.42초 → 4.25초였다.
자동 확장이 질문 이해의 출력량을 늘려 검색 전 대기 시간이 증가한다.

측정 범위
---------

기준선도 새 등록 별칭·단어 경계 규칙을 사용한다. 모델의 자동 확장만 껐다.
따라서 이 수치는 예전 모든 검색 코드와의 비교가 아니라 자동 확장의 추가 효과다.
관련성 검토 AI와 답변 생성 이전의 상위 8개 검색을 측정했다.
문서 임베딩 생성, 관련성 검토와 답변 생성은 시간에 포함하지 않는다.
일부 질문에는 관련 기록이 8개보다 많아 Recall@8의 최대값이 100%보다 낮다.

질문 이해를 확장 전후에 각각 실제 실행하고 순서를 번갈아 적용했다.
그 출력을 보존한 뒤 최종 중의어 검사 규칙으로 검색을 재실행했다.
질문 이해 시간은 처음 실제 측정값을, 검색 시간은 최종 재실행 값을 사용했다.
평균 시간은 이 환경에서 한 번씩 측정한 값이며 반복 부하 측정이 아니다.
원시 응답·후보 ID·점수·시간·확장 내역은 multilingual_results.json에 있다.

검증
----

* 전체 Python 회귀 검사 252개 통과. API 검사도 통과했다.
* 이후 추가한 딥러닝 별칭을 포함해 검색 표현·C++ 검사 60개 통과.
* 검색·오타 교정 관련 검사 87개 통과.
* 번역·발음 설명, 기존 하이라이트·오타 교정 화면 검사 통과.
* Chrome에서 번역·발음·별칭 강조, 실패 복귀, HTML 리터럴 표시 검사 통과.
* 기존 Chrome 검색 사유·과거 응답·변경·삭제 기록 검사 통과.

소스 코드·빌드한 선택적 C++ 모듈은 새 프로세스에서 검증했다.
실행 중인 사용자 앱과 모델 서버는 재시작하지 않았다.

재현
----

실제 모델 출력까지 다시 측정::

    python -u -m evaluation.multilingual_search

저장된 실제 모델 출력으로 최종 검색을 재검사::

    python -u -m evaluation.multilingual_search --replay evaluation/multilingual_results.json --output .local/multilingual-replay.json
