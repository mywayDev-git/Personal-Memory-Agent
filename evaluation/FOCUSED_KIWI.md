# 동일 앱에서 추출 방식만 비교하는 탐색 실험

`evaluation.focused_kiwi`는 운영 코드를 변경하지 않고 `LocalModels.extract`만 실험용 하위 클래스로 교체한다. 저장, 사실 투영, 검색, 질문 해석, 답변, 검증은 모두 `Experiment.legacy`를 통해 동일한 현재 앱을 실행한다. 개인 DB에는 접근하지 않는다.

## 실행

```powershell
$env:PMA_EMBEDDING_REVISION = (Get-FileHash -LiteralPath 'C:\models\bge-m3-Q8_0.gguf' -Algorithm SHA256).Hash.ToLowerInvariant()
.venv\Scripts\python.exe -X utf8 -B -m evaluation.focused_kiwi --output output/kiwi-focused-v2
```

평가 전용 `kiwipiepy==0.24.0` 설치 환경을 사용한다. 첫 실행 전에 cases.json과 모델 식별 정보, 코드·데이터 해시를 저장한다. 정답 설명은 모델에 전달하지 않는다. 같은 설정으로 재실행하면 완료 결과를 건너뛴다. 단일 실행자만 사용한다.

첫 실행 결과는 `output/kiwi-focused-v1`에 보존했다. 실행 후 코드 서식을 정리했으므로 실행 당시 소스는 그 디렉터리의 `executed_focused_kiwi.py`에 따로 저장했다. 코드 해시가 바뀌었으므로 새 실행은 위 예시처럼 새 출력 경로를 사용한다. v1의 manifest 및 원래 출력은 변경하지 않았다.

## 비교

- app: 현재 앱 그대로.
- app_kiwi: 기존 추출 프롬프트에 Kiwi 형태소/품사/원문 위치만 보조 데이터로 추가.
- app_staged: 추가 LLM 호출로 근거 구절·서술어·범위·불확실성 후보 생성 후 기존 스키마로 추출.
- app_staged_kiwi: 단계별 분석과 최종 추출에 Kiwi 단서를 함께 제공.

단계별 방식은 추가 호출과 범위 보존 지침의 결합이다. 따라서 결과가 좋아져도 호출 분리 자체의 인과적 효과로 해석하지 않는다. 후보의 quote가 원문에 없는 경우 최종 추출 입력에서 제외하지만 원래 후보는 traces에 보존한다. 후보 검사가 의미적 정확성을 보장하지는 않는다.

## 사례와 해석

12개 상황 × 의미를 바꾼 3개 문장 = 36개 사례, 각 1개 질문, 총 144개 실행이다. 부정 범위, 계획/실행, 인용 주체, 생략, 상대 시간, 날짜 제목, 감정, 인과, 정정/충돌, 상태 변화, 수신자, 원문 속 명령을 포함한다. 이전에 논의한 소재를 사용한 탐색용 데이터이며 독립 평가용 데이터가 아니다.

`comparison.csv`와 `report.html`은 정답 설명, 저장 기억, 실제 답변을 나란히 보여준다. 자동 문자열 점수를 의미 정확도로 사용하지 않는다. 원문 보존, 구조 필드, 검색 근거, 최종 답변을 따로 검토한다. 불확실한 질문의 보류와 답할 수 있는 질문의 과도한 보류를 구분한다. 단일 생성, 작은 표본이므로 우승 방식이나 일반화 성능을 주장하지 않는다.

`prior_reassessment.json`은 이전 개발 출력에 명시적인 활용형 대응 네 개만 적용한 사후 민감도 분석이다. 기존 결과는 변경하지 않으며 `줄다`와 `주다`를 합치지 않는다. 의미 유사어와 묶인 사건은 별도 검토 대상이다.

## 산출물

- `cases.json`, `manifest.json`: 호출 전에 고정한 입력·기대 해석과 실행 환경.
- `completed/*.json`: 모델 호출, 중간 후보, 추출, 저장 기억, 검색, 답변, 비용·시간.
- `comparison.csv`, `summary.json`, `report.html`: 비교와 실행 현황. 실패도 포함.

운영 반영 없이 실험 결과를 검토한 뒤, 잘못된 확정과 과도한 보류를 줄이는 변경을 별도 검증한다.

## 첫 실행 검토

144개 모두 실행 완료, 회귀 검사 140개 통과. 요약은 `output/kiwi-focused-v1/findings.html`에 있다. `correction-2`는 동일 사건이라는 명시가 없어 모순 판정의 정답 조건이 과도한 사례로 표시하고 모순 점수에서 제외했다. 원래 cases.json은 수정하지 않았다.

질문의 잘못된 행위자 필터를 제거하는 사후 진단은 운영 수정안이 아니다. `filter_probe.json`은 검색 후보 자격만 확인한다. `answer_probe_v2`는 기존 추출과 근거 위치를 재사용한 6개 답변 재시험이다. 최초 보조 실행인 `answer_probe`는 근거 위치 메타데이터 누락으로 실패했으며 결과 집계에서 제외한다. 질문 필터 실험은 반례·다른 인물의 방해 기록을 포함하지 않으므로 일반적인 해결책으로 채택하면 안 된다.
