실제 모델 CPU·GPU / Python·C++ 비교
===================================

2026-10-21 CPU 해석 정정: 아래의 ``-ngl 0``만 사용한 실행은 보조 GPU 연산과
KV 오프로딩을 명시적으로 차단하지 않았습니다. 과거 관측값은 보존하지만 순수
CPU 전용 성능이나 10초 달성 근거로 사용하지 않습니다. 새 CPU 측정은
``--device none --no-op-offload --no-kv-offload``도 사용하며, GPU가 없는 실기기의
검증과 구분합니다.

측정일: 2026-10-19. 브랜치: codex/cpu-gpu-performance.

결과
----

앱을 재시작했고 실제 앱 PID 41672의 C++ 확장 로드와 합성 자기검사 호출 1회를 확인했다.
앱 루트 응답은 200이며, 기존 GPU 모델 서버 두 개는 8081·8082에서 정상 복구됐다.
별도의 합성 DB 웹 앱에서도 실제 HTTP 검색·기억 기반 답변 요청의 C++ 호출을 확인했다.
검색은 C++ 경로에서 관측 중앙값이 CPU 7.6%, GPU 10.8% 짧았다. 모델 HTTP 시간도 달라졌으므로 전체 차이를 C++ 순수 기여로 단정하지 않는다.
GPU 답변 전체 차이는 약 0.9%로, 반복 변동에 비해 작아 유의미한 개선으로 판단하지 않는다.
이 대량 부하 조건의 CPU 답변은 두 경로 모두 CONTEXT_LIMIT 오류로 완료하지 못했다. 성공 답변 시간 중앙값을 계산할 수 없다.

입력·측정 방법
---------------

개인 DB를 성능 입력으로 열지 않았다. 실제 GPU Qwen/BGE로 짧은 합성 선물 기록 하나를 추출·임베딩한 뒤,
원문과 실제 임베딩을 유지하고 새 기록·기억 ID로 1만 건을 만들었다. 네 조건은 동일한 DB 내용을 사용했다.
각 기록이 같은 질문에 관련되는 밀집 부하 실험이다. 다양한 의미의 실제 기록 1만 건을 대표하지 않는다.
사용 모델: Qwen3-8B-Q4_K_M, BGE-M3-Q8_0. 하드웨어: i7-13700(16코어/24논리), 16GB RAM, RTX 3060 8GB.
GPU는 두 서버 -ngl 99, CPU는 두 서버 -ngl 0으로 실행했다. 스레드는 서버 기본값을 사용했다.
CPU는 GPU가 장착된 동일 PC에서 오프로딩만 끈 실험이다. 물리적으로 GPU가 없는 기기는 검증하지 않았다.
컨텍스트 16,384/8,192, 생성 최대 4,096, 개별 모델 제한 180초, 대화 예산 300초와 근거 검증을 양쪽에서 유지했다.
조건별 준비 1회 후 5회가 목표이며 Python→C++와 C++→Python 순서를 번갈아 실행했다.
CPU 답변은 준비 실행 양쪽 실패 후 첫 측정 반복에서도 양쪽이 실패해 반복 오류 중단 정책으로 종료했다.
기록 추출·모델 로딩은 측정 시간에서 제외했다. 검색·대화 엔진 전체와 실제 모델 통신·검증을 포함했다.
HTTP/UI 포장 계층은 별도 실제 HTTP 검증으로 확인했다. 브라우저 렌더링 시간은 측정하지 않았다.
첫 GPU 모델 확인 뒤 원래 앱/모델 PID가 사라져 원래 프로세스 환경을 보존하지 못했다.
복구에는 최초 관찰한 GPU 실행 인수, 기존 --test 실행 모드와 이미 존재하는 기본 앱 데이터 폴더를 사용했다.
실험 중에는 사용자 앱 DB를 합성 DB로 바꾸지 않았다.

메모리 (GiB)
-------------

RAM은 벤치마크 Python과 두 모델 서버의 working set 합계를 1초 간격으로 관측했다.
두 백엔드 서비스가 같은 프로세스에 함께 유지되므로 두 캐시의 공통 상주 비용도 포함된다.
RAM 중앙값은 각 요청에서 관측한 최고값 5개의 중앙값이며 최고값은 반복 중 최댓값이다.
CPU 답변은 성공 0회, 측정 실패 1회씩의 관측값으로 표기한다. 준비 실행은 아래 표에서 제외했다.

조건                 Python RAM 중앙/최고   C++ RAM 중앙/최고    VRAM 최고 PY/CPP
---------------------------------------------------------------------------------------------
CPU 검색                 5.616/6.209            5.615/6.998            1.371/1.371
CPU 답변(실패)             7.988/7.988            8.630/8.630            1.407/1.428
GPU 검색                 4.660/4.903            4.837/4.857            7.633/7.633

VRAM은 GPU 장치 전체 사용량이며 데스크톱과 CUDA 컨텍스트 등을 포함한다. CPU 모드의 VRAM 숫자는 모델 GPU 오프로딩 사용량이 아니다.
시작 시 관측한 가용 물리 RAM은 약 0.72GiB였고 실제 working set 회수와 모델 캐시에 따른 변동이 컸다.
이 표로 C++의 추가 RAM 비용이나 메모리 절감을 분리해 판단할 수 없다. 이전 독립 매칭 실험의 메모리 결과와 구분해야 한다.

C++ 실제 실행·복구 검증
-----------------------

* 실제 앱 PID 41672에서 _keyword_native.cp314-win_amd64.pyd 로드를 확인했다.
* 같은 PID의 합성 시작 검사에서 native_calls=1, Python과 equal=true를 확인했다. 이 검사는 사용자 기록을 읽지 않는다.
* 측정 중 C++ 검색은 요청당 실제 네이티브 호출 1회, GPU 답변은 2회였다. CPU 답변 실패 전에도 네이티브 호출 2회를 확인했다.
* 앱 루트 200, 복구한 8081·8082 모델 health=ok와 -ngl 99 설정을 확인했다.
* 별도 합성 웹 앱의 실제 HTTP 검증은 다음과 같다. 준비 실행이 없는 단발 진단이므로 5회 중앙값과 직접 비교하지 않는다.

  - search: HTTP 200, ok, 4.14초, C++ 1회 / 10,000행.
  - memory_chat: HTTP 200, answered, 140.14초, C++ 2회 / 20,000행.

HTTP 답변도 model_checked, 근거 8개와 예상 책 답변을 확인했다. 사용자 앱 DB를 이 검증에 사용하지 않았다.
검증용 HTTP 서버와 측정용 모델 서버는 종료하고 운영 앱과 원래 GPU 모델 서버를 유지했다.

품질·한계·재현
---------------

* GPU 답변 10회 모두 model_checked, 인용 근거와 예상 책 답변을 확인했다. CPU 답변은 두 경로 모두 실패해 답변 품질 통과로 집계하지 않는다.
* 모델·프롬프트·검증·컨텍스트·시간 제한은 비교 중 변경하지 않았다. 핵심 소스 해시도 시작 시점과 일치한다.
* 관측 누락을 막기 위한 숫자 메모리/HTTP 메타데이터 기록만 측정 프로세스에 추가했다. 원문이나 프롬프트 내용은 성능 로그에 추가하지 않았다.
* C++/DB 표적 테스트 14개, 실패 통계 회귀 테스트 2개와 새 측정 도구 린트를 통과했다.
* 이전의 모델 대체 구현 벤치마크 개선율을 실제 AI 답변 개선율로 확대 적용하지 않는다.
* 이 결과에서 후속 병목은 모델의 근거 선택/추가 검색과 CPU 컨텍스트 예산 관리다. 이번 비교에는 새 최적화를 섞지 않았다.
