변경 파일
---------

  사실·제안 분리, 개인 사실 중복과 인용 없는 기록 확인 주장 차단.
* pma/chat/store.py: 기존 request_input JSON으로 모드 저장/복원/재시도 충돌 처리.
* pma/static/index.html, chat.js, style.css: 모드 선택, 재시도 모드 보존,
  코드 블록·인라인 코드·간단한 Markdown 표, 제안·추론 표시.
* tests/test_conversation_modes.py, test_automatic_chat.py, chat_ui.test.mjs: 회귀 검증.
* README.md: API 호환성 및 사용법.

기존 검색 API, 테이블 스키마, 근거 인용/삭제 수명주기는 유지했다.
기존 conversation_type=mixed 필드는 남기고 conversation_mode=hybrid를 추가했다.
실제 코드에는 ChatAction 열거형이 없어 불필요한 새 실행 체계는 만들지 않았다.
기존 로컬 모델 서버를 공유하며 모델 로딩은 추가하지 않았다.

실모델 관찰
-----------

실행 중인 로컬 생성 서버(8081) 및 임베딩 서버(8082)를 사용했다.
개인 DB 대신 output 아래 별도 DB에 가상 프로젝트 기록 1개를 넣었다.
임베딩 파일 SHA-256을 확인하여 평가 설정에 적용했다.

LLM 호출은 /v1/chat/completions만 집계했으며 토큰 계산과 임베딩 호출은 제외했다.
내 기억 사용은 일반 설명이 필요한 경우 혼합 경로로 확장될 수 있다.
호출 수는 질문, 추가 검색, 검증 재시도에 따라 달라진다.

일반 대화는 이전 async/await 설명을 이어 코드 예제를 생성했다.
기억 답변은 원문의 순차 검색 처리 구조를 인용했다.
마지막 혼합 답변은 해당 사실과 병렬/비동기 처리 제안을 분리했다.
처음에는 제안을 개인 사실에 섞거나 개인 사실을 인용 없이 반복하는 사례가 있어
사실 전용 질문과 반복/기록 언급 차단을 추가하고 회귀 테스트로 검증했다.
표의 실모델 수치는 마지막 기록 언급 차단 규칙 추가 직전 관찰값이다.
그 규칙은 실제 관찰된 유형을 재현하는 자동 테스트로 검증했으며 실모델 시간을 재측정하지 않았다.

검색 정책은 관찰한 4개 시나리오에서 4/4 일치했다. 이는 일반 답변 정확도나 검색 정확도의
통계적 평가가 아니다. 원문 사실과 후속 대화 연결은 확인했지만, 다양한 데이터의 의미 정확도와
일반 코딩 품질은 별도 평가가 필요하다. 지연은 단일 실행값이며 평균이나 성능 보장이 아니다.

원시 결과는 output/modes-live/report.json의 첫 두 항목과
output/modes-live-final/report.json에 저장되어 있다.
