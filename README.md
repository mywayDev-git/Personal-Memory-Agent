# Personal-Memory-Agent

대학 캡스톤 I 프로젝트. 일기를 로컬에서 저장하고, 나중에 질문하면 관련 기억과 요약 근거를 보여줍니다.

## 시연 화면 실행

Windows에서 [Node.js 24 LTS](https://nodejs.org/en/download)와 [llama.cpp](https://github.com/ggml-org/llama.cpp/releases/)를 준비합니다. 백엔드는 `C:\llama.cpp\llama-server.exe`를 사용합니다. NVIDIA GPU가 있는 PC에서는 Windows x64 CUDA 실행 파일과 같은 릴리스의 CUDA DLL을 이 폴더에 둡니다. CPU로 실행할 때는 Windows x64 CPU 패키지를 사용합니다.

저장소가 없다면 PowerShell에서 시연 브랜치를 내려받습니다.

```powershell
git clone --single-branch --branch twins1909/event-graph-model-comparison-20261109 https://github.com/mywayDev-git/Personal-Memory-Agent.git Personal-Memory-Agent-demo
Set-Location .\Personal-Memory-Agent-demo
```

1. 저장소 루트에서 **백엔드**를 켭니다.

   ```powershell
   node server.cjs
   ```

2. [모델 준비 화면](http://127.0.0.1:4319/baseline)에서 생성 모델을 선택합니다. 처음이라면 **Qwen3.5 2B → 선택 모델 준비**를 눌러 생성 모델과 **Qwen3 Embedding 0.6B**의 다운로드 및 검증을 마칩니다. 기존 `.models` 폴더를 옮겼다면 모델을 다시 받을 필요는 없습니다. **모델 서버 켜기**로 미리 로드할 수 있습니다.
3. 새 PowerShell 창을 열고 같은 저장소 루트에서 **시연 프론트**를 켭니다.

   ```powershell
   node .\demo-frontend\serve.cjs
   ```

4. 두 창을 열어 둔 채 [시연 화면](http://127.0.0.1:4320/)에 접속합니다. 별도의 `npm install`이나 Python 환경이 필요하지 않습니다. 모델 평가를 실행 중이라면 평가가 끝난 뒤 시연하세요.

## 사색 대화와 감정 갈무리 확인

1. **서재 홈**에 `어제 민수와 도서관에서 발표 자료를 정리했다.`를 입력하고 **시작하기**를 누릅니다. **사색 대화**에서 **기록하기**를 누르면 저장됩니다.
2. `어제 민수와 어디서 발표 자료를 정리했어?`라고 물으면 해당 날짜의 기록을 바탕으로 답합니다. 사용한 요약 근거는 답변 아래에 표시됩니다.
3. 같은 대화에서 `그거 언제였지?`라고 물으면 로컬 모델이 최근 대화로 질문의 대상을 해석한 뒤 저장된 기록을 다시 검색합니다. 여러 사건 중 무엇인지 모호하면 먼저 묻습니다. 대화 내용 자체는 개인 사실의 근거로 쓰지 않습니다.
4. **감정 갈무리**에서 감정을 고르고 `기분이 우울해서 학교 운동장을 산책했더니 마음이 한결 편해졌다.`를 저장합니다. **달력에서 보기**에서 기록일과 감정을 확인할 수 있습니다.
5. **사색 대화**에 `오늘 마음이 무거운데 어떻게 하면 좋을까?`라고 입력하면 먼저 답변합니다. 관련 기억이 있으면 답변 아래에 표시합니다. 참고한 기억이 없고 같은 내용의 기록도 없으면, 사용자 말풍선의 **이 내용 저장** 버튼으로 일기에 추가할 수 있습니다.

날짜는 한국 시간(Asia/Seoul) 기준입니다. `8일에 뭐 했어?`는 이번 달 8일의 기록만 검색합니다. 일기는 입력에 날짜가 없으면 오늘로 저장합니다. 일정은 날짜가 빠지거나 시작 시각이 애매하면 사색 대화에서 한 번 더 묻습니다.

사색 대화의 최근 문맥은 현재 브라우저 페이지의 메모리에만 유지합니다. **새 대화**는 별도의 문맥으로 시작하고, 페이지를 새로고침하면 대화 목록과 문맥이 초기화됩니다. 사용자가 저장한 일기와 일정은 유지됩니다.

새 일기와 재요약은 저장 전에 로컬 모델로 원문과 요약의 인물·행동 대상·시간·부정·계획·이유·중요 내용 누락을 비교합니다. 의미 보존이나 문장별 근거를 확인하지 못하면 해당 구간을 원문 그대로 보관합니다. 이 검사는 저장 시 모델 호출을 추가하므로 노트북에서는 저장이 더 오래 걸릴 수 있습니다. 기존 저장 기록은 자동으로 바꾸지 않으며, 다시 검사하려면 요약 기억 관리에서 **원본으로 다시 만들기**를 사용합니다.

개인 기억 답변의 기존 두 번째 모델 호출은 문장별 근거 검사로 사용합니다. 모델은 답변 항목마다 근거 문장 ID를 선택하고 앱이 실제 인용문을 연결합니다. 답변을 두 번 같은 표현으로 복사하는 검사는 하지 않습니다. 답할 근거가 있으면 해당 기록을 인용하고, 대상이 분명해도 내용이 없으면 확인할 수 없다고 답합니다. 특정 인물의 이름이 기록에 없다는 이유로 불참을 단정하지 않습니다. 대상이 모호하면 로컬 모델이 추가 단서를 묻습니다. 모델이 수행하는 의미 검사는 정확성을 보장하지 않으므로 실제 입력으로 확인해야 합니다.

후속 질문의 대상은 최근 대화의 후보 ID로 선택합니다. 표현을 똑같이 복사하지 못했다는 이유로 요청을 실패시키지 않습니다. 답변 처리에 실패한 경우에도 사용자 질문은 현재 대화의 대상 해석에 참고할 수 있도록 유지하고, 오류 메시지는 문맥이나 사실 근거에 넣지 않습니다.

새 일기의 감정은 로컬 모델이 요약할 때 함께 판단해 **서재 보관소**에 표시합니다. 감정 단서가 없는 일기는 **단서 없음**으로 표시합니다. 기존 일기는 [요약 기억 관리](http://127.0.0.1:4319/summary)에서 **원본으로 다시 만들기**를 누르면 감정을 판단할 수 있습니다.

모델 파일은 로컬 `.models`에, 일기와 평가 기록은 로컬 `.local/baseline`에 저장합니다. 다른 PC에서 새 기록으로 시연하려면 모델 파일만 옮기거나 다시 준비하세요. 평가 워크벤치와 저장 방식에 대한 자세한 설명은 [BASELINE.md](BASELINE.md)를 참고하세요.

## 현재 보완한 동작

- 최근 대화로 후속 질문의 대상을 해석한 뒤 기록을 다시 검색합니다. 이전 AI 답변을 사실 근거로 사용하지 않습니다.
- 참석 여부를 묻는 질문은 조회로 처리합니다. 일정의 날짜·시각을 확인하던 중 새로운 사건 문장이 들어오면 새 요청으로 분류합니다.
- 반복되는 답변 문장을 제거하고, 선택한 근거에 없는 시간대와 이유의 근거 누락을 검사합니다. 검사에서 발견한 오류는 한 번 재작성을 요청합니다.
- 날짜별 일정 조회는 해당 날짜의 기록을 각각 확인합니다. 과거 날짜의 감정 공유는 그때의 경험으로 응답하도록 지침과 처리를 보완했습니다.
- 단순한 주고받기 문장에는 준 사람·받은 사람·물건을 구분하는 보조 검사를 적용했습니다. 복합 문장 전체의 의미를 검증하는 기능은 아니며, 아래 실제 시험에서 관계 오류가 여전히 확인됐습니다.

## 2026-11-11 실제 모델 확인 결과와 남은 문제

노트북의 **Qwen3.5 2B Q4_K_M**과 **Qwen3 Embedding 0.6B Q8_0**으로 M1 검색, Top-K 3 조건에서 확인했습니다. 실행 중인 모델 서버는 유지하고 최신 코드를 별도 프로세스에서 실행했습니다. 저장된 일기 사본으로 검색·답변 과정을 시험했으며, 기존 일기는 변경하지 않았습니다.

시험 일기:

```text
11월 10일 지현에게 책을 받았다. 민수에게는 선물을 주지 않았다. 일기로 기록해 줘.
```

| 질문 | 실제 최종 답변 | 의미 판정 | 처리 시간 |
| --- | --- | --- | --- |
| 11월 10일에 누가 나에게 책을 줬어? | 11월 10일 지현에게 책을 주지 않았어요. | 오답: 지현이 준 사람이며 사용자가 받은 사람 | 341초 |
| 11월 10일에 민수에게 선물을 주지 않은 이유는 뭐야? | 11월 10일 민수에게 선물을 주지 않은 이유에 대한 기록을 확인할 수 없습니다. | 정상: 이유를 추측하지 않음 | 61초 |
| 11월 10일에 지현에게 무엇을 받았어? | 11월 10일에는 지현에게 책을 받았어요. | 정상 | 78초 |
| 11월 10일에 민수에게 선물을 줬어? | 11월 10일에는 민수에게 선물을 주지 않았어요. | 정상 | 69초 |

이 네 문항 중 세 문항이 정상이라는 결과이며, 전체 모델 정확도나 일반적인 성공률을 뜻하지 않습니다. 첫 질문의 시간에는 검색 색인 재생성과 재시도가 포함되어 다른 질문과 직접적인 속도 비교를 하면 안 됩니다. 모든 문항은 저장·분류·화면 전체의 종합 시험이 아니라, 저장된 기록에 대한 조회 분류·검색·답변 경로의 실제 모델 시험입니다.

**주고받는 방향과 인용의 의미 연결은 아직 해결되지 않았습니다.** 첫 답변은 지현·책에 대한 잘못된 주장에 민수·선물의 부정 문장을 인용했습니다. 인용 위치 검사가 통과해도 답변의 인물·물건·부정이 정확하다는 뜻은 아닙니다. 원문 보존과 규칙 검사만으로 이 문제를 해결했다고 판단하면 안 됩니다. 이유를 확인할 수 없다는 답변의 말투도 해요체로 완전히 통일되지는 않았습니다.

## 실습실에서 이어서 비교하기

1. 기존 저장소에서는 현재 브랜치가 `twins1909/event-graph-model-comparison-20261109`인지 확인한 뒤 `git pull --ff-only`로 업데이트합니다. 새 PC라면 위의 해당 브랜치 복제 명령을 사용합니다.
2. RTX GPU용 llama.cpp 실행 파일과 같은 릴리스의 CUDA DLL을 `C:\llama.cpp`에 준비합니다. 백엔드와 시연 프론트의 실행 명령은 위와 같습니다. 실행 중인 백엔드는 업데이트 후 재시작하고 시연 페이지도 새로고침합니다.
3. 모델 준비 화면에서 비교할 생성 모델을 선택해 준비하고, 시연 화면 상단에서도 같은 모델을 선택합니다. 임베딩 모델과 검색 설정은 유지합니다.
4. 테스트 일기를 한 번 저장한 뒤 위 네 질문을 각자 독립적으로 실행합니다. 모델을 바꿀 때는 **새 대화**로 시작해 이전 답변이 섞이지 않게 합니다. 같은 입력·코드·프롬프트·검색 설정을 유지하고 모델명·양자화·하드웨어를 함께 기록합니다.
5. 모델 변경 직후의 색인 준비·재구축 시간과 이후 질문의 처리 시간을 구분합니다. 최종 답뿐 아니라 실제 인용문이 인물·물건·부정·이유를 뒷받침하는지 직접 확인합니다. 후속 질문·일정 누락·감정 대화는 별도의 시연 확인 항목으로 남겨 둡니다.

모델 파일, 개인 일기 DB, 로컬 시험 산출물은 Git에 포함하지 않습니다. 새 PC에서는 모델 준비와 위 시험 일기 입력을 다시 진행하세요.
