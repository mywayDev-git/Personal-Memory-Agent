# 자연 문맥 독립셋 v1.0.0

기존 질문에 덧붙이는 확장본 대신 새 자연 문맥 자료만 담은 별도 데이터셋입니다. 기존 56개 통제 원문·질문은 포함하지 않습니다. 기존 데이터셋과 실행 기록은 그대로 보존합니다.

| 구분 | 이야기 | 원문 | 질문 |
| --- | ---: | ---: | ---: |
| 한 원문 안의 자연 문맥 연결 | 8 | 8 | 48 |
| 서로 다른 원문 간 연결 | 4 | 8 | 24 |
| 위 이야기에서 만든 짧은 대조 | 12개 이야기의 변형 | 12 | 12 |
| 합계 | 기본 이야기 12개 | 28 | 84 |

기억 범위는 24개입니다. 짧은 대조는 원래 이야기와 별도의 범위로 격리하며, 원래 이야기의 첫 질문에 필요한 의미만 보존합니다. 기본 이야기와 대조를 독립 이야기 24개로 합산하지 않습니다.

업무 6개와 일상 6개를 포함합니다. 기본 이야기 원문 합계는 사례당 1233~1353자입니다. 담당자 인계·조건·정정·동명이인·인용 시간·추측과 확인·상충 보고·계획과 실제 수행·지출 범위를 다룹니다. 각 이야기의 제목과 질문은 cases.json에서 확인할 수 있습니다.

원문·질문·정답 초안은 앞서 작성한 자연 문맥 자료와 동일하며, 분리를 이유로 의미나 정답을 바꾸지 않았습니다. 데이터는 이 폴더에 복사된 독립 스냅샷입니다. 실행·검증·재구축 때 기존 v1 통제셋이나 v2 통합본을 읽지 않습니다. 이전 통합본은 이 독립셋과 구별해 보존합니다.

## 파일과 사용

inputs.json은 원문 입력, annotations.json은 사례별 질문·주석 연결, sources.json은 앱용 원문과 분리된 gold입니다. contexts.json은 사례별 검색 범위, questions.json은 질문과 대표 답변·필수 의미·금지 추론·근거 그룹, connections.json은 기대 연결 관계입니다. sentence_inventory.json은 원문의 작성 문장과 의미 묶음을 연결합니다. coverage.json은 세 프로필, manifest.json은 버전·개수·해시·한계를 담습니다.

앱에서 **pma-context-v1.0.0 · 자연 문맥 독립셋**을 선택합니다. 한 원문48문항·원문 간24문항·짧은 대조12문항을 별도로 고르거나 전체84문항을 선택할 수 있습니다. 조회만으로 모델이 실행되지 않습니다.

264개의 문장 의미 묶음과 12개 대조 주석, 59개 연결 관계는 작성자 초안입니다. 문장 묶음 하나에 여러 주장이 들어갈 수 있으므로 원자 사실 수나 의미 정확도로 해석하지 않습니다. 근거 위치·참조·범위 격리는 자동 검사하며 의미 정확성·완전성은 독립 검토 전입니다. 모델 입력에 정답·질문 주석·연결 관계를 넣지 않습니다.

모든 자료는 개발용 합성이며 실제 모델 성능·토큰수는 미측정입니다. 원문 전체 입력을 사용하고 실제 가져오기 분할이나 전역 개체 통합을 구현했다는 뜻은 아닙니다. 원문이 사례당 1~2개라 순위 성능을 일반화할 수도 없습니다. 공식 전체 변수 포괄셋이나 미공개 최종 평가셋이 아닙니다.

## 독립 재구축

이 폴더만 복사한 뒤 `python -B build.py`로 재구축할 수 있습니다. 자체 definition.json·lib.mjs·README.md만 사용하고 기존 데이터셋·개인 DB·모델·네트워크를 참조하지 않습니다. 생성된 원문/질문 파일을 직접 고치기보다 정의를 변경한 새 버전을 만들어 기록합니다. 기존 실행 결과는 재채점하지 않습니다.
