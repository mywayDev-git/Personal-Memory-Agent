# 장문 개발셋 v1.0.1

원문 56개와 연결 질문 56개를 가져온 별도 개발 데이터셋입니다. 모든 데이터는 합성이며 정답은 작성자 초안입니다. 모델 평가를 실행하거나 기존 데이터·프롬프트·모델 설정을 교체하지 않았습니다.

## 파일과 연결

| 파일 | 역할 |
| --- | --- |
| inputs.json | 원문 입력: ID, text, reference_time, entry_mode만 포함 |
| annotations.json | 같은 ID의 질문·필수 의미·구조 기대값·금지 추론·근거 구간 |
| upstream/ | ZIP의 원본 JSON 3개를 바이트 그대로 보존 |
| sources.json | 현재 앱용 원문·별도 gold. 모델에는 gold를 전달하지 않음 |
| contexts.json | 사례당 독립된 검색 범위, 합성 owner 1개·원문 1개 |
| questions.json | 질문과 정답 초안. 대표 답변·기대 행동은 미주석(null) |
| import_plans.json | 4000 Unicode 문자/줄바꿈 기준의 분할 계획. 실행 산출물이 아님 |
| coverage.json | 6개 프로필. 공식 489개 변수 연결은 아직 미작성 |
| manifest.json | 버전·개수·해시·출처·교정 이력·실행 경로·한계 |
| lib.mjs | 독립 검증기. 기존 데이터셋의 검증 규칙을 변경하지 않음 |

원본 annotations.json의 위치는 Unicode code point 기준입니다. 앱 sources.json의 근거 위치는 UTF-16 [start,end) 기준으로 변환합니다. 원본 ID에는 검사 의도가 드러나므로 모델 입력의 source_id·owner_id에는 불투명한 식별자를 사용합니다. profile·family·pair_group·위치·질문·정답은 추출 입력에 넣지 않습니다. source gold의 facts 배열은 기존 앱과 연결하기 위한 자리이며 실제 내용은 **목표 근거 구간 60개**입니다. 문서 전체 의미 사실 60개라는 뜻이 아닙니다.

## 프로필

| 선택 | 수 | 검사 의도 |
| --- | ---: | --- |
| smoke | 8 | 역할·부정·조건·정정·동명이인·인용 시간·행위자 미상·원인 미상의 짧은 대조군 |
| core | 24 | 위 8개 의미 × 3000자 앞·중간·끝 |
| sentence | 8 | 역할·부정·조건·정정 × 600/1800자 단일 문장. 목표는 끝에 위치 |
| boundary | 6 | 3999/4000/4001/7999/8000/8001자. 가져오기 분할 계획의 경계 |
| dependency | 4 | 8500자, 원거리 정정·역할·원인·충돌. 떨어진 두 구간이 모두 필요 |
| stress | 6 | 12000/24000자 앞·중간·끝. 조건부 계획 계열에 한정 |

모든 사례는 development입니다. 길이와 위치를 바꾼 같은 pair_group은 독립 표본으로 합산하지 않습니다. 최종 평가셋이나 전체 변수 포괄셋으로 부르지 않습니다. 방해 문장 전체는 정답 주석되지 않았습니다. 대표 답변 문장과 기대 행동은 원본에 없으므로 임의 생성하지 않았습니다. 모델 토큰수는 미측정입니다.

## 교정

원본 LI-import-4001은 실제로 4013자였습니다. 그대로인 목표 문장을 [3973,4001)로 옮겨 4001자로 맞췄습니다. 질문·필수 의미·구조 기대값·금지 추론은 그대로입니다. 해당 입력과 annotations의 text, 근거 위치, 문자·바이트 수와 해시만 변경했습니다. 나머지 55개 원문은 원본과 같습니다. 원본 ZIP과 upstream JSON은 수정하지 않습니다.

## 현재 앱에서 확인하는 방법

1. http://127.0.0.1:4319/baseline 에서 데이터셋 **pma-long-v1.0.1 · 장문 56개**를 선택합니다.
2. 처음에는 짧은 대조군 8개가 표시됩니다. 데이터 프로필로 다른 묶음이나 전체를 선택합니다.
3. 질문을 선택하면 원문, 문자 수, 검사 위치, pair_group과 판정 기준을 볼 수 있습니다.
4. 판정 기준에는 필수 의미·구조 기대값·금지 주장·목표 근거 구간이 표시됩니다.
5. 프로필·범위 선택 자체는 모델을 호출하지 않습니다. 실제 실행은 사용자가 실행 버튼을 눌렀을 때 시작합니다.

현재 실행 경로는 **raw_original_v1(원문 전체)**입니다. text_import는 입력의 용도를 나타내며, 원본 제품의 4000자 가져오기 동작을 구현하거나 실행했다는 뜻이 아닙니다. 가져오기 분할 계획은 별도로 표시합니다. 현재 앱의 검색 청크는 기존 방식 그대로이고 이 분할 계획과 다릅니다. boundary/dependency 원문을 여기서 실행해도 실제 제품의 가져오기 경계 검증으로 보고하면 안 됩니다.

문서 기준시각은 reference_time으로 보존하며 저장 시각(created_at)과 작성자는 미제공입니다. 현재 추출 프롬프트는 created_at 기준의 상대 시간 규칙을 사용하므로 문서 기준시각 해석을 비교하려면 다음 프롬프트·어댑터 작업에서 별도 버전으로 정의해야 합니다. 모델과 v5 프롬프트 이식은 이 데이터셋 구축에 포함하지 않습니다.

## 재현과 검증

앱 폴더에서 `python -B tools/build-long-dataset.py --zip <원본 ZIP 경로>`로 JSON 파일을 재구축합니다. Python 표준 라이브러리만 사용하며 ZIP 안의 코드는 실행하지 않습니다. 기존 lib.mjs와 README.md를 포함한 이 버전 폴더를 유지해야 합니다. 결과는 입력 ZIP과 빌더가 같으면 동일합니다.

`node --test tests/long-dataset.test.cjs`는 개수·해시·원본 보존·교정·근거 위치·프로필·기억 범위 격리·정답 유출 방지·실행 설정을 확인합니다. 실제 모델을 로드하지 않으며 의미 성능 검증을 대신하지 않습니다. 사람 검토가 끝나기 전에는 필수 의미의 문자열 일치로 PASS를 부여하지 않습니다.

다음 데이터 작업은 56개의 필수 의미·구조 기대값·금지 추론을 사람이 원문과 대조하고, 대표 답변·기대 행동이 필요하면 명시적으로 주석하여 새 데이터 버전을 만드는 것입니다.
