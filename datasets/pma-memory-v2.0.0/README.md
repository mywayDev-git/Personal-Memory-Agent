# 누적 기억 비교셋 v2.0.0

- 원문 288개 = 개발 192개 + 최종용 96개. 36개 합성 기억 묶음에 각 8개 원문을 둡니다. 서로 다른 묶음은 독립 사용자입니다.
- 기본 질문 288개 + 통제 입력 변형 72개 = 실행 항목 360개. 변형은 8개 질문을 재사용하며 독립 질문으로 합산하지 않습니다.
- 같은 원문 안에 길이 채우기 반복을 넣지 않았습니다. 원문 사이의 사건 재인용은 중복 판별을 위한 명시적 조건입니다.
- 정답과 원문별 의미 묶음은 작성자 초안입니다. 독립 사람 검토·실제 모델 평가·실제 토큰 측정은 수행하지 않았습니다.
- 기억 2·5·8개와 순서를 통제합니다. 500·1000·1500·1900 실제 토큰 구간을 충족한다고 주장하지 않습니다. 토큰수는 사용자가 실행할 때 측정합니다.
- 현재 R0-Full의 원문·메타데이터 2048토큰 예산을 넘으면 비교 제외입니다. 입력 예산·모델·프롬프트·합격선은 변경하지 않았습니다.
- 최종용은 개발 자료와 인물·사건·표현을 분리했으나 작성자 독립 검토나 외부 비공개 인증을 뜻하지 않습니다. 최종용 조회 사실은 사용자 판단 대상입니다.
- 후속 질문은 고정 대화 맥락을 사용합니다. 실제 생성된 이전 답변의 오류 전파·대화 전체 경로 평가는 별도입니다.
- 삭제·권한·저장·캐시·가져오기·UI·장애 동작은 이 고정 원문 자료만으로 검증하지 않습니다. 489개 변수는 부분 연결·누락·별도 검사로 표시합니다.
- 기존 데이터 파일과 과거 실행 결과는 수정하거나 재채점하지 않습니다. 새 자료의 정답을 기존 모델 출력에 맞춰 만들지 않았습니다.
- 한 실행 최대 150문항 제한을 유지합니다. 개발 A·개발 B·통제·최종 프로필은 각각 제한 이내입니다. 전체 360문항은 나눠 실행해야 합니다.

## 이전 검토 반영

평소 선호 미상과 부정을 구분하고, 꽃무늬 접시 주문 여부를 명시했습니다. 시안 제목·예시 이름 수정을 모두 질문에 포함했습니다. 표 단위 검토와 전체 보고서 검토를 구분하고 사건·열람·저장 날짜를 본문에 명시했습니다. 실제 방문일 미상, R-721 원본 범위, 증빙 파일 미확보를 명확히 했습니다. 질문 범위 밖 배경 설명을 필수 답변으로 요구하지 않습니다.

## 재생성

`python build.py`는 자체 definition.json에서 JSON 산출물을 재생성합니다. 모델·네트워크·다른 데이터셋을 사용하지 않습니다. 의미 정답의 독립 검토는 별도입니다.
